# 1. 背景与目标

## 1.1 业务背景

  

平台服务的是"食堂 / 餐厅采购 + 生鲜供应商履约"的场景。

链路上有两类主体：

**门店（采购方）** 在自己的系统里维护商品主数据——商品、SKU 及其编码规则，并把 SKU 分配给对应供应商；供应端**直接复用**这份门店 SKU 数据，不另建主数据、不做二次同步；

**供应商** 不新建商品档案，只做三件事：

|   |   |
|---|---|
|事项|内容|
|给价（唯一必填动作）|认领门店推来的 SKU，给一个货品价格。|
|补生意上的事实（全部选填）|包装单位、产地、保质期、货品别名、第三方编码、内部备注。|
|必要时停一停|这段时间不卖，就临时停售；想再卖，恢复在售。|

  

「商品与价格」是整条交易链的**起点模块**，它的产出被四条下游链路直接消费：

|消费方|消费内容|缺失后果|
|---|---|---|
|询价与报价|供货货品、货品价格（作为报价默认单价）|报不了价、报价行没有初始价|
|直采下单|货品价格已设的供货货品|直采列表里根本不出现这个 SKU|
|分拣发货|货品别名、包装单位（选填，缺了回退门店品名 / 不打印包规）|拣货单认不出货、验收核对不上包规|
|验收结算|商品形态、包装单位、成交价快照|扣重口径错、对账口径错|

## 2.2核心场景

|   |   |
|---|---|
|场景名称|场景内容|
|门店分来新货，供应商给价（高频）|门店在后台一次性新增了几十个 SKU 并分配给本供应商，供应端直接复用这份数据，落成「待设价」。供应商打开**供货价格维护（B03）**，侧栏那个橙色数字就是"还有多少条没给价"；逐条进详情，**只填货品价格**就能保存，保存完立刻是「已设价」，这个 SKU 从这一刻起进询价单、进直采列表、可以被安排分拣。包装单位、产地想起来再补，不影响任何流程。（支持模版批量修改导入）|
|给已设价的货补资料、调价（低风险，随时可做）|供应商在**供货价格维护**页点「编辑」进详情页，补包装单位（验收时和门店包规核对要用）、产地（印在送货单和溯源标签上）、别名（拣货单用）、内部备注（只有自己看）。改价格会留一条变更记录，并立即作用于"从这一刻起的动作"。|
|这段时间不卖，先停一停（可逆）|某个货货源断了、季节性下架、这周不想做，点「临时停售」并选原因。停售期间它不进新询价、不排分拣，**已提交的报价与在途订单照常履约**；想过一阵再卖，回来点「恢复在售」就行——记录一直都在，不需要重新确认，也不影响任何评分。<br><br>**附：门店侧的两种动作，供应端两套处理，不许混**<br><br>- **下架**（这段时间不卖了，SKU 还在）→ 供应端「已失效」，只读留痕；门店重新上架后**自动恢复**到失效前的状态，无需任何人工操作。<br>- **删除**（门店不要这个东西了）→ 供应端**逻辑删除**，退出清单、退出所有 Tab、不进待办、不占分母；数据一条不删，历史订单、送货单、验收单、对账单、发票仍能追溯。|

  

## 2.3 完整流程

  

|步骤|页面|系统给了什么|走不通时会怎样|
|---|---|---|---|
|1|供货价格维护|门店分配给本供应商的 SKU **直接复用**，供应端只在一张扩展表上维护价格与扩展信息；无推送机制、不轮询、无定时刷新（BR-19）|数据接入异常时按当前已有数据展示，本页不提供刷新入口（EC-11）|
|2|供货价格维护（B03）|直接复用门店 SKU 即「待设价」，按 SKU 编码正序排好，侧栏徽标 +1|找不到货：按 SKU / 品名 / 别名筛（FR-B03 筛选区）|
|3|货品编辑|门店定义的 9 项只读；扩展信息 7 项可填，**只有货品价格必填**|价格填 0、留空、非数字：前端标红拦截，不落库（BR-06）|
|4|供货价格维护（B03）|保存成功即「已设价」，进入可报价池|包装 / 产地空着不影响（BR-05）|
|5|询价单（C01）|门店发起询价后，供应端侧栏「询价单」亮起待报价徽标；单里**只含「已设价」的 SKU**|没设价：直采列表不出现（BR-10、BR-24）|
|6|报价单编辑（C03）|逐行填供货价（默认 = 货品价格）、供不上的行标「不可供」；提交即传平台|本轮要供的行没填价：前端标红拦截并指出哪几行，请求不发出（BR-18 同源）|
|7|报价单详情 → 中标结果（C06、C07）|截止后先进「待公示」（结果灰置），门店确认后逐行看中标 / 未中标，中标行可跳正式订单|想提前看结果：按钮灰置，C07 给守卫页并说明是"未开始比价"还是"待门店确认"（BR-29）|
|8|供货价格维护 · 临时停售（这条分支任何时候都可能发生，不必等前面走完）|不想卖时停售，随时恢复在售|停售期间不进新询价，在途订单照发（BR-12）|

# 3. 术语与核心口径

## 3.1 术语

  

|术语|业务定义|
|---|---|
|门店商品|门店定义的一个商品（如"老豆腐"），由门店系统维护，编码随数据一并下发|
|门店 SKU|门店商品的某个销售规格（如 5kg/箱），**供货、报价、分拣的最小单位**|
|供应商货品|门店 SKU 加上供应商补的价格与选填信息；不是新档案，本质是一条"认领记录"|
|待设价|门店已分配、供应商还没给价的状态。**它是状态，不是待办入口**；待办只在 B03（唯一待办落点，BR-21）|
|已设价|**货品价格已填且大于 0**。就这一条，不看包装单位、不看产地（BR-05）|
|货品价格|供应商对该货品的单价（元/单位），是报价默认单价与直采成交价的来源|
|临时停售|供应商主动"这段时间不卖"。不进新询价、不排分拣；在途订单照常履约；随时恢复在售|
|已失效|门店把商品**下架**导致的联动状态。只读留痕，门店重新上架后自动恢复|
|门店已删除|门店把商品**删除**。供应端逻辑删除：退出清单与全部 Tab，数据留存供历史单据追溯|
|货品别名|供应商内部叫法，仅用于拣货单、库位标签、仓库检索，**不上任何对外单据**|
|商品形态|毛菜 / 净菜 / 半成品，由门店定义，决定验收扣重口径|
|数据来源|门店分配给本供应商的 SKU 由供应端**直接复用**；供应端不落地全量主数据，仅在一张扩展表上维护价格与扩展信息。无推送机制、不轮询、无定时刷新、无手动刷新入口（V1.0.1 起）。|
|均价估算|按**当前时间口径**（默认近 3 个月）取历次变更价，做简单平均。口径由用户主动设置、只有一处，全站均值一起生效。**仅供定价参考，不参与任何计算**|
|询价单（RFQ）|门店（采购方）向供应商发出的采购询价，含若干**采购行**（SKU + 需求量）。一个档口的一次询价即一张单|
|采购行|询价单的最小单位：到「门店 · 档口 · SKU」粒度，含需求量|
|报价单（QUOTE）|供应商对**每一张**询价单的应答，与询价单一一对应；含若干**报价行**|
|报价行|报价单的最小单位，对应询价单的一个采购行；含供货价与可供状态|
|供货价|供应商在本轮报给该行的单价（元/单位）。默认 = 货品价格，可逐行调整；**提交时锁定**，与当前货品价格无关（BR-31）|
|可供 / 不可供|行级供货状态。**不可供 = 本轮不供这一行**，不填价、不计入报价合计、不进比价；它是供应商表达"这轮不供"的唯一入口（BR-25）|
|已提交|报价已传上平台、但询价尚未截止的状态；截止前仍可进 C03 修改，以最后一次提交为准|
|待公示|已提交且已截止、但门店尚未确认报价的中间态；比价结果已产生但**对外（对供应商）灰置**，等待门店确认公示（BR-29）|
|未参与|从未在截止前提交过报价的询价单；系统中**不存在对应的报价单**，无任何报价数据|
|比价|门店对多家供应商报价的横向比较与选标|
|中标结果|按 SKU 逐行标出中标 / 未中标，并锁定成交价；中标行须全量履约|

```
侧栏 ──► 询价单 ──「查看」──► 询价单详情 ──「参与报价 / 修改报价」──► 报价单编辑 ──「提交报价」──► 我的报价单
询价单详情 ──「查看报价」（已报价 / 已中标 / 未中标 / 待公示）──► 报价单详情
我的报价单 ──「修改报价」（已提交）/「查看」（其他）──► 报价单详情
报价单详情 ──「看中标结果」──► 中标结果（已出结果时；待公示 / 已提交时按钮灰置或守卫）
中标结果 ──「查看正式订单」（有中标时）──► 订单中心
待办中心 ──「询价待报价」──► 询价单详情（直接进对应单的报价）
```

**跨模块交接点（唯一一条）**

```
供货价格维护 ──设价成功、状态翻为「已设价」──► 进入可报价池 ──门店在该门店 · 档口发起询价──► 询价单（C01）
```

这一条链要连起来看才顺：**B03 里给完价，货才可能出现在 C01 的询价单里**；反过来，C 侧的任何动作都不回写 B 侧 —— 报价单里的价格是提交时的快照（BR-31），之后在 B02 / B06 改价不会追溯已提交的报价。

**落点规则**：任何"改完状态"的动作，落点必须是**货品改完之后真正所在的那个 Tab**，不是"你进来的那个 Tab"，也不是写死的某个 Tab。理由很直接 —— 改完状态货品就会换列表，落到旧 Tab 上它必然不在，用户看到的就是"操作完它消失了"，会当成失败重做一遍。

- 保存成功：按保存后的状态落地（仍在停售 → 临时停售 Tab；有价 → 已设价 Tab）。
- 停售：落「临时停售」Tab。
- 恢复在售：有价落「已设价」，无价落「待设价」。
- 批量导入（V4.3）：写入结果页先留在原地（它就是这一批的凭据）；点「返回供货价格维护」时，若这一批**全是已设价** → 落「已设价」，若**混有仍在停售的** → 落「全部」，否则那些停售的货在「已设价」里同样找不到。

三条容易走错的路径，单独说明：

- 在 B03 任一行点「设价 / 编辑」进 B02，保存后**一律回到 B03** —— 现在只有一个列表入口，不存在"回到另一个列表"的情况；但 Tab 要按上面的规则重算。
- 在 B02 点「临时停售」，确认后落 **B03 的「临时停售」Tab**（不是回到原 Tab 空等）：停售的货已不在可报价池里，落点必须能立刻看见它，否则用户会以为操作没生效。
- 在「临时停售」Tab 点「编辑」进 B02、只改了个别名就保存，出来必须**还停在「临时停售」Tab**：它的状态没变，就不该被送去「已设价」。

# 4. 核心业务对象

## 4.1 业务对象

|对象|谁产生|它代表什么|供应商能改吗|
|---|---|---|---|
|门店商品与门店 SKU|门店系统（供应端直接复用，不落地第二份）|门店在卖的货，包含商品名、编码、形态、分类、品牌、规格、单位|**不能**。全部字段只读，页面上也没有可改的入口|
|设价记录|供应商第一次保存货品价格时产生|"这个 SKU 我供，价是这个数"，加上包装单位、产地、别名等选填信息|能，改的是自己填的那部分|
|停售记录|供应商点「临时停售」后产生|"这段时间不卖"，含停售原因与说明；在途订单不受影响|能，随时恢复在售|
|失效记录|门店下架或删除商品时由系统自动生成|这条货因为什么失效（下架还是删除）、失效前是什么状态、还欠着多少没发完的订单|不能，只能查看；下架类在门店重新上架后自动恢复|
|价格变更记录|每次改价自动产生|改后的价、谁改的、什么时候改的、从哪改的|不能改也不能删，是留痕|
|询价单（RFQ）|门店发起|一张采购需求：档口、行、需求量、报价截止|不能改需求；只能应答|
|报价单（QUOTE）|供应商首次提交报价时生成|"这张询价单我这么报"：每行供货价 + 可供状态|截止前可改（再提交即覆盖）|
|报价快照|每次提交报价时由系统落库|提交那一刻的逐行供货价与可供状态，锁定不变|不能改；是 C06 / C07 的唯一数据源|
|中标结果|门店确认比价后回写|逐行中标 / 未中标，含成交价与生成的订单号|不能改|

## 4.2 派生规则

|   |   |
|---|---|
|项|规则|
|**状态**|一条货品的状态永远由"门店有没有下架 / 删除它、供应商有没有停售它、它有没有有效的货品价格"算出来，不单独存一个状态字段。这样不会出现"状态显示已设价、其实价格是空的"这种自相矛盾。|
|**已设价**|只看**货品价格 > 0** 这一条。包装单位、产地不参与判定。|
|**均价**|按当前时间口径（默认近 3 个月）取历次变更价，做简单平均，每次打开趋势页现算，不预先存储。口径是用户主动设的，改了之后 B06 列表、趋势图均价线、B02 的 ±50% 偏离预警一起跟着变；口径内一条改价记录都没有时显示「—」，不退回全部历史。|

# 5.业务规则 

  

以下规则跨页面生效。若某个页面的局部做法与本章冲突，以本章为准。

|编号|主题|核心规则|说明 / 原因|
|---|---|---|---|
|BR-01|主数据只有一份，且只读|商品目录只来自门店——即门店分配给本供应商的 SKU，供应端直接复用、不落地第二份；供应商不可新增、删除、修改八个锚点字段（商品名称、商品编码、SKU 编码、商品形态、商品分类、品牌、销售规格、单位）；不提供“自建货品”入口。门店下发的商品编码与 SKU 编码原样保存、原样展示：不自己编号、不套用编码规则、不做格式校验与修正、不改大小写、不截断。|编码是门店与供应商的共同语言，平台改写会导致“平台编码—门店编码—历史单据”三处对不上，截断超长编码等于凭空造新 SKU；允许改商品名/规格/形态则无法同表比价，锁死锚点报价才有公信力。|
|BR-02|一个商品多个 SKU，各自独立|同一商品不同规格是不同 SKU；每个 SKU 独立设价、独立维护价格与包装，不可合并、不可继承；详情页须提示同商品下还有哪几个 SKU 及其状态。|大板豆腐和小板豆腐单价、包装成本不同，合并会算错钱。|
|BR-03|形态由门店定义，供应商不判定|商品形态由门店定义，供应商不可修改、不参与任何形态判定；不设形态异议入口：形态不作为校验项、不弹提示、不阻断提交；供应商按门店口径报价即可。若认为门店标错形态：先临时停售、别按错规格设价，再截图反馈运营改 SKU，由门店侧修正后供应端即时可见；供应商侧不产生工单、不进入审批流。|—|
|BR-04|门店分配即建立供货关系，没有「认领」动作|门店把一个 SKU 分配给本供应商，供应端立刻建立供货关系并落成「待设价」；供应商不需点“确认我要供”、不需“认领”；所有锚点字段实时读门店数据，门店改了立刻看到改后值。|该模块唯一有信息量的输入是价格；让用户先点“我供”再填价，等于把一件事拆成两步，还多出一个会积压的收件箱。|
|BR-05|已设价只有一个要素：货品价格 > 0|判定「已设价」的唯一条件：货品价格已填且大于 0。包装单位、产地、保质期、货品别名、第三方编码、内部备注全部选填，不参与状态判定、不做保存校验、也不做询单报价校验；缺这些字段照样能进询价单、直采列表、分拣与发货，只是送货单、溯源标签对应位置为空。状态与待办数一律由实际数据算出，不允许手写、写死。判定只有一个入口：保存、列表状态、报价能否提交、直采能否收录四处用同一判定。|包装单位答“怎么打包”、产地答“从哪儿进的”，属于“填了更好看”而非“能不能卖”；设成必填会导致门店一分配，供应商得先补两项无关资料才能给价。多处各写一套会出现“能保存、但报不了价”的两套口径。|
|BR-06|价格必须有效|货品价格必填、必须大于 0、最多两位小数；超过 9999 视为多输一位，拦截。填 0、留空、负数、非数字一律视为“未设置”，不允许保存成有效价格。校验时机统一约定见 BR-18。|—|
|BR-06a|均价的时间口径|「均价」= 当前口径内历次变更价的简单平均；口径为用户级配置，五档（近 1 / 3 / 6 / 12 个月 / 全部历史），默认近 3 个月。硬约束：①全站只有一处配置、一个计算入口，B06 列表、明细弹层、B02 保存时 ±50% 预警调同一函数、读同一口径值；②口径只决定取哪些样本，不改算法（仍简单平均，不加权、不移动平均）；③口径内无样本显示 `—`，不回退全部历史；B02 的 ±50% 预警无样本时直接跳过。|各处自己算会出现“列表按 3 个月、预警按全部历史”，两个均价并存说不清哪个对；回退会让配置变摆设，用户设 1 个月却看到一年均价，以为设置没生效。完整规格见 FR-B06-7。|
|BR-07|价格只影响未来，不追溯|改价对“从这一刻起的动作”生效：报价行报价、直采下单成交价、新生成订单行；不回溯已提交报价单、已生成订单、已出对账单。所有涉及改价的页面须把这句话直接放在界面上，不能只写在文档里。|—|
|BR-08|改价必须留痕|任何价格变更（详情页单条改、批量调价）都要留一条变更记录，含改后价格、时间、操作人、改动来源；禁止静默改价，不提供“删除某条价格记录”入口。|—|
|BR-09|失效只停未来|失效不影响已承诺订单；还有未完成订单行、门店又已下架的货品，仍须正常分拣、发货、验收、结算；失效只影响“还能不能接新单”。|—|
|BR-10|没设价就不能进业务|判断货品能否报价、能否被直采收录，只看 BR-05 那一条；待设价、临时停售、已失效、门店已删除的货品一律不进询价单、不进直采列表、不排分拣；其中已失效优先于其他状态——即便曾设过价，也不得进入报价和直采。|—|
|BR-11|恢复是自动的，且按失效前的样子还原|门店重新上架后，数据直接复用，失效状态自动解除，不设“确认恢复”人工动作。恢复按失效前状态还原：失效前已设价的恢复后直接可报价；失效前待设价的恢复后仍待设价；失效前临时停售的恢复后仍停售。扩展信息完整保留，不重置、不清空。|「门店又上架了」这件事没有第二种答案。|
|BR-12|停售不是拒绝，也不中断在途履约|临时停售只登记“这段时间不卖这个货”，不改变供货关系、不删任何记录；停售原因必填，补充说明选填。已设价且有在途订单的货品同样可停售：①只影响未来——从停售那刻起新询价单不再包含该货品，退出可报价池；②不影响已有——已提交报价单、已中标订单、已生成送货单仍按当时价和原货品信息正常履约，不拦截、不要求重新确认；③资料不丢——包装单位、产地、价格、别名全部保留，恢复在售后原样带出；④没有“惩罚”——不计违约、不影响评分、不进履约档案。|供应商停供往往因毛利、产能或货源变化，而非否认历史报价；若停售连带终止在途订单，供应商就不敢用，只能拖到失效，问题会推到分拣和验收才暴露。|
|BR-13|停售必须写原因|停售弹窗「为什么停售」为必选项：货源临时中断 / 季节性停售 / 规格不符 / 毛利太低 / 产能不足 / 不是我的货；补充说明选填，200 字以内。原因对运营可见，运营据此判断要不要改 SKU。|停售是未来要回来看的决策，靠回忆不如靠记录。|
|BR-14|别名不上对外单据|货品别名只用于拣货单、库位标签、仓库内部检索；送货单、验收单、对账单、发票一律打印门店商品名。|—|
|BR-15|均价仅供参考|均价是当前时间口径内历次变更价的简单平均，只用于判断当前价相对历史偏高还是偏低，不参与下单、比价、结算任何计算；时间口径只决定取哪些记录来平均，不改变简单平均算法本身，不引入加权、不引入移动平均。|—|
|BR-16|重复操作不重复生效|设价、停售、恢复在售重复点击或重复提交只生效一次，返回第一次结果，不报错、不产生第二条记录。两人同时改同一条货品价格时，后提交者收到“该货品已被其他人修改，请刷新后重试”，对方数据不被覆盖。同一次门店数据变更里同一 SKU 出现多条时以最后一条为准，覆盖前一条，不产生两条供货关系、不弹重复提示。|—|
|BR-17|全程可追溯|设价、改价（含批量）、停售、恢复在售、失效联动、门店删除全部写入操作日志，保留不少于 12 个月；被系统拒绝的操作同样留痕。|—|
|BR-18|校验在提交前完成，由前端拦截|所有必填与格式校验在用户点提交时由前端判断并当场标红，不把请求发出去等接口返回错误。①标红精确到字段，下方给出具体原因；②多处不合规全部标红，并在字段上方汇总“有 X 项不符合要求，本次没有保存”；③用户修正某字段后该字段标红立即消失，不需再点提交验证；④拦截只提示不重置，已填内容原样保留。后端仍做同样校验作为兜底，防止绕过页面直接调用，但属防御性路径。|不允许“提交—退回—再找哪里错了”的反复试探路径。|
|BR-19|数据直接复用门店 SKU，供应端仅维护单一扩展表|门店分配给本供应商的商品（门店 SKU）由供应端**直接复用**，不做二次同步、不轮询、不定时刷新；价格与扩展信息（包装单位、产地、保质期、别名、三方编码、备注）由供应端在**一张扩展表**上维护，门店 SKU 主数据不在供应端落地。本页不展示任何「推送 / 同步」状态，也不提供手动刷新入口（V1.0.1 起取消推送机制与手动刷新）。|—|
|BR-20|门店「删除」与「下架」分两路处理|下架（`已失效`）：这段时间不卖、SKU 还在；供应端只读留痕，记录失效类型、时间、失效前状态、未完成订单行数；门店重新上架后自动恢复（BR-11）。删除（`门店已删除`）：门店不要这个东西了；供应端做逻辑删除——退出「供货价格维护」全部 Tab（连「全部」也不显示）、不进待办数、不占任何分母，但数据一条不删，历史订单、送货单、验收单、对账单、发票仍能追溯回该 SKU。|下架 = 还要你看见（迟早要恢复）；删除 = 不该再占你注意力。清单里只留需要你判断的货。|
|BR-21|待办只有一个落点：供货价格维护（B03）|「待设价有几条」是全模块唯一“现在就得动手”的数，只挂一处：B03（V4.1 起承接原「我的供货清单」待办信号）；其他页面不重复提醒、不重复着色。|—|
|BR-22|列表一律按 SKU 编码正序|B03 列表（含五个 Tab）一律按 SKU 编码正序，不做“待办优先”。|编码里带着商品序，同商品多规格自然相邻（S1001301 与 S1001302 挨着），报错规格概率比按时间乱序低；做成“待办优先”行会随状态跳动，第二次找同一行需重新扫，列表天天要看，稳定性比“聪明”值钱。想看该我处理的，用筛选或 Tab，不靠排序暗示。|
|BR-23|术语：货品维度与询价维度分开叫|货品维度（本模块）：待设价 / 已设价 / 临时停售 / 已失效 / 门店已删除。询价维度（询价与报价模块）：待报价 / 已报价。两个维度不许互相借用词；货品维度禁止出现「待报价」「未报价」「未设价」「已报价」。价格列统一：有价写 `¥xx.xx`，无价一律写 `—`；为什么没价由状态列说明。|同一个“没价”在同一个格子里有多种说法，扫列表就得多读一遍才知道说的是同一件事。|
|BR-24|询价单只含「已设价」的 SKU|门店发起询价时筛选“能报的货”，询价单不出现待设价、临时停售、已失效、门店已删除的行；供应商在 C02 / C03 看到的每一行都是可正常报价的。|—|
|BR-25|本轮不供只能逐行选「不可供」|供应商表达“这轮这个货我不供”的唯一方式：报价单里把该行标为「不可供」；标后输入框冻结、不填价、不计入报价合计、不进比价。临时停售只影响下一轮新询价（BR-12），本轮已生成询价单照常可报、可填价——不必为“这轮不想供”去停售一个还在卖的货。|—|
|BR-26|没有草稿：提交即传上平台|报价单编辑页不落库草稿；点「提交报价」那一刻才生成 / 更新「已提交」报价单并上传平台；截止前可再次进 C03 修改，以最后一次提交为准。没有“先存一半”、没有“提交后还能撤回”。|—|
|BR-27|取消二次确认|原型曾有的“C04 报价二次确认”整屏删除；提交报价不经过二次确认弹窗，直接生效。|二次确认不产出任何新信息，只多一次点击。|
|BR-28|没有「放弃报价」|“放弃报价 / 撤回报价”概念整体下线（原 C08 删除）；未参与 ≠ 放弃：未参与是“从未提交过”，系统中本就没有这张报价单；不存在“提交了又放弃”的中间态。|—|
|BR-29|比价结果分两段不可见|中标结果在两种情况下对供应商不可见，必须灰置或守卫：①已提交（询价未截止）——比价根本没开始；②待公示（已截止、门店未确认）——比价已产生但还没公示。两种情况 C06 的「看中标结果」按钮分别表现为「修改报价」或可点但灰置；C07 对两种情况都渲染守卫提示页，措辞分开（“询价进行中，尚未开始比价” / “已截止，待门店确认后公示”）。|报价期内摆出“几中标几未中”等于把底价漏给对手方。|
|BR-30|中标结果逐行独立|选标按 SKU 逐行进行，一行中标不影响另一行；结果以“中标行 / 未中标行”呈现；中标行须全量履约，不允许挑行履约。|—|
|BR-31|报价单价是提交时锁定价|报价单里的供货价 = 提交那一刻的价，与当前货品价格无关；之后改货品价格、看价格趋势都不回查、不追溯已提交的报价单（与 BR-07 同源）。|—|
|BR-32|金额与行数一律由快照反推|报价单的“报价合计”“报价行数”“不报价行数”，以及报价单列表的“中标合计”，全部由对应快照（QDETAIL）实时计算，不手写、不写死；“中标合计”只累加真正中标的行（全部中标 + 部分中标，且扣掉未中标行）。|部分中标的单若把整张报价合计算进“中标”，金额会虚高。|
|BR-33|状态与计数从数据派生|所有状态标签、页签计数、徽标、列表行数、剩余时间提示一律按实际数据现算；原型里手写数字的地方都改成函数（如 `RFQ.filter(r=>[r.st](http://r.st)==='待报价').length`）。|避免“页头说 2、列表说 3”对不上。|
|BR-34|询价单与报价单状态联动|提交报价后，对应询价单从「待报价」翻为「已报价」，C02 右上角入口随之从“参与报价”变为“修改报价”；翻转由提交动作同步完成，不靠人工维护。|—|
|BR-35|报价行数 / 采购行数|列表里 `分子 / 分母`：分子 = 我已报（或已提交）了几行，分母 = 门店要了几行。一行都没报时分子为 0 且走次要色（不额外加红，状态列已说明“待报价”）；报满才用正常色。|—|
|BR-36|询价单详情只显示“我自己的报价”|C02 的「报价」列只放供应商在报价单里填的价；未填价显示 `—`（表示“这行你还没给价”，不是“报了 0 元”）。|两个长得差不多的数放同一行最容易被读成一个（3.24 和 3.10 到底哪个是我的？）。|
|BR-37|采购主体最小颗粒度到档口|同店不同档口的询价、报价、订单都是独立的两张；列表 / 详情 / 订单都带「采购档口」列，不允许合并统计。|—|

  

# 6.状态及流转

## 6.1 状态定义

**货品状态**

|状态|含义|这时能做什么|算不算待办|能不能报价|
|---|---|---|---|---|
|待设价|门店已分配，供应商还没给价|设价、临时停售|**是**（供货价格维护 B03，唯一待办）|否|
|已设价|货品价格已填且 > 0|编辑（改价 / 补选填）、临时停售、看趋势|否|是|
|临时停售|供应商主动"这段时间不卖"|恢复在售、编辑资料|否|否|
|已失效|门店把商品下架，尚未重新上架|只能查看失效原因；等门店上架后自动恢复|否|否|
|门店已删除|门店把商品删除|什么都不能做，也不显示在任何清单与 Tab 里|否|否|

**询价单（RFQ）状态**

  

|状态|含义|右上角入口|能不能进报价|
|---|---|---|---|
|待报价|已收到询价，还没提交过报价|参与报价（进 C03）|能|
|已报价|已提交过至少一次报价（截止前）|修改报价（进 C03）|能（截止前再改）|
|待公示|已提交且已截止，门店尚未确认报价|查看报价（进 C06，结果灰置）|不能（已截止）|
|已中标|门店确认比价，本单有中标行|查看报价（进 C06 → C07）|不能（已截止）|
|未中标|门店确认比价，本单全未中|查看报价（进 C06 → C07）|不能（已截止）|
|未参与|从未在截止前提交过报价|无报价单入口|不能（已截止且无单）|

**报价单（QUOTE）五态**

已提交 / 待公示 / 全部中标 / 部分中标 / 未中标。（"已提交"与"待公示"是同一张单在截止前后的价格可见性分界；"全部中标 / 部分中标 / 未中标"是门店确认后的结论。）

## 6.2 状态流转

**商品**

|编号|动作|从什么状态|变成什么状态|作用|谁能做|
|---|---|---|---|---|---|
|T-01|设价（首次保存货品价格）|待设价|已设价|写入价格；生成价格历史第 1 条；B03 徽标 -1|主账号、采购|
|T-02|改价（已设价状态下保存新价格）|已设价|已设价（不变）|写一条价格变更记录（改后价 / 时间 / 操作人 / 来源）；同步报价行；不回溯历史单据（BR-07）|主账号、采购|
|T-03|编辑选填字段并保存|待设价 / 已设价 / 临时停售|不变|只更新包装单位、产地、保质期、别名、第三方编码、备注；价格未变则不留痕|主账号、采购（仓库仅能改别名 / 包装单位）|
|T-04|临时停售|待设价 / 已设价|临时停售|写入停售原因、时间、说明；退出可报价池；在途报价与订单不受影响（BR-12）|主账号、采购|
|T-05|恢复在售|临时停售|已设价（有价）/ 待设价（无价）|删除停售记录；扩展信息原样保留；回到 B03 时按 SKU 编码回到原位|主账号、采购|
|T-06|门店下架（商品级或 SKU 级）|待设价 / 已设价 / 临时停售|已失效|记录失效类型、时间、失效前状态、未完成订单行数；从 B03 与可报价池移除；数据保留|系统（随门店数据变更自动）|
|T-07|门店重新上架|已失效|回到失效前状态|数据直接复用后自动解除失效状态，无人工确认；扩展信息完整保留（BR-11）|系统（随门店数据同步）|
|T-08|门店删除|任意状态|门店已删除|逻辑删除：退出 B03 全部 Tab、不进分母；数据留存供历史单据追溯|系统（随门店数据变更自动）|

四条容易搞混的地方，单独说清：

1. **T-01 与 T-02 是同一条规则的两个结果**，区别只在"之前有没有价"，不在"走哪个页面"。从清单的「设价」、从供货价格维护的「设价」、从「编辑」进去改价，都是同一个保存动作。
2. **停售不改变"供货关系"，只改变"在不在售"。** 所以恢复在售不需要任何确认，也不需要重新填资料。
3. **失效态下仍记着原来的状态**，恢复是**还原**，不是从零开始（BR-11）。
4. **门店删除是不可逆的**：供应商侧没有"恢复"入口。门店若重新把同一个 SKU 分配给本供应商，视为一条新的供货关系，按当前数据落成待设价。

# 7.功能需求 

## 7.1 B03 供货价格维护

**FR-B03-1 页面目标与入口**

门店主数据的唯一视图，同时承接原「供货确认」与「失效商品」两屏的职能。它承担三件事：**看见变化、找到下一步、承接唯一待办**——待办信号（侧栏橙色徽标 + 页头橙色标签 + 橙色「待设价」数字）V4.1 起由本屏统一承接（原「我的供货清单」已合并）。入口：侧栏（带橙色徽标）、其他页面跳转。

**FR-B03-2 页面构成**

顶部汇总，中间五个状态 Tab + 筛选区，列表，底部汇总条与分页。

**FR-B03-3 页头与汇总口径**

副标题：

```
待设价 X（橙） · 已设价 Y [· 临时停售 S] · 已失效 V · 覆盖 K 家门店 · 可参与报价 Z [· 另有 W 个不在清单（临时停售 a · 门店下架 / 删除 b）] [· 门店已删除 D 个（不显示）]
```

各段口径（口径固定，数字现算，不写死）：

- **待设价 X**：门店已分配、还没给价的 SKU 数，用**橙色**。这一段的数字、侧栏徽标、右上角 tag 三处同源同数（BR-21）。
- **已设价 Y**：有货品价格（> 0）的 SKU 数。停售与失效的另计，不混进这一段。
- **可参与报价 Z**：已设价、且未临时停售、未被下架 / 删除的 SKU 数，直接对应 BR-05 —— 它回答的是"我现在能报几个货"，与 C03 报价单里的可报行数同口径。
- **另有 W 个不在清单**：`W = 临时停售 a + 门店下架 / 删除 b`。**这一段是为了回答"我的货怎么少了"**：被挡在可报价池之外的每一类都给个数，且必须能对上总账 —— 原型数据：`可参与报价 14 + 待设价 28 + 临时停售 2 + 已失效 4 = 48`（在管），再加门店已删除 2 = **50**（全量目录）。
- **门店已删除 D 个**：单独一句、不进 W；它们的量级只在这里露一次面（BR-20）。
- 「另有…」整段在没有被挡掉的货品时不渲染；包装单位、产地等空字段同样不得留下空括注残句。

右上角 Tag：有待设价时显示**「待你设价 X 个」**（琥珀色）；全部已设价时显示「全部已设价」（绿色）。这是全模块唯一的橙色待办高亮，与侧栏徽标、页头橙色「待设价」数字同源同数（BR-21）。

右上按钮：`导入`、`导出`（「导入」排在「导出」左侧，两者是一对：导出去核账，导进来批量填）。`导入` 的悬浮说明：_"批量为待设价 / 已设价 / 临时停售的货品填写货品价格与扩展信息"_。本页无「手动刷新」入口（V1.0.1 起取消推送机制与手动刷新，数据直接复用门店 SKU）。

**FR-B03-4 五个 Tab**

顺序 = 商品在供应商手里走过的路（门店已删除的不进来）：

|Tab|内容|Tab 提示（底部汇总条右侧）|
|---|---|---|
|全部|在管全部 SKU|数据直接复用门店 SKU，这一屏始终与门店一致 · 按 SKU 编码正序，同一商品的多规格上下相邻|
|待设价|还没给价的 SKU|门店分配的 SKU 即「待设价」· 填完货品价格并保存，自动变「已设价」（其余字段选填）|
|已设价|已设价的 SKU|已设价即可参与询价、直采与发货；点「编辑」改动价格 / 包装 / 产地等，只影响之后的新单，不回溯历史单据|
|临时停售|供应商自己停售的 SKU|临时停售不是拒绝：随时恢复在售，不删记录、不影响评分，停售期间不进新询价|
|已失效|门店下架的 SKU|只有「下架」算失效，只读留痕，重新上架后数据直接复用自动恢复；门店「删除」的不在这一页 —— 供应端已逻辑删除|

Tab 上的数字只是"筛出来有几条"，**不着色**（橙色只留给本屏待办）。每个 Tab 各存各的页码，来回切换不掉页。

**FR-B03-5 列表字段（10 列，百分比定宽）**

|#|列|宽度|展示规则|
|---|---|---|---|
|1|SKU 编码|10.5%|等宽小字|
|2|商品名称 / 销售规格|15%|主行商品名，副行规格；超长省略号|
|3|单位|5.5%|居中，紧跟商品名后|
|4|形态|7.8%|形态标签|
|5|分类|9.3%|省略号|
|6|品牌|7.8%|省略号|
|7|门店|11.9%|省略号|
|8|货品价格|9.8%|有价 `¥x.xx`（等宽加粗右对齐）；无价 `—`（灰）|
|9|状态|9.8%|状态标签，**承载全部辅助信息（见 FR-B03-6）**|
|10|操作|12.6%|见 FR-B03-7|

**为什么用百分比定宽**：以前列宽自适应，内容一少就在中间留出一大片空白，横向扫读时视线要跨过一段没有信息的区域。定宽铺满后，每一列的位置在翻页、切 Tab 后都不变，扫读靠位置而不是靠找表头。

**为什么去掉商品编码列**：SKU 编码已能唯一确定一行；商品编码对"这行货是什么"没有增量信息，对"报错规格"也没有防护作用。去掉之后，省下的宽度给了商品名和门店。

**FR-B03-6 状态列承载的辅助信息（悬停可见）**

原来单独占一列的「状态说明（报价 / 停售来源）」被取消，内容转进状态格的悬停提示——不再占一列宽度，但一个字也没丢：

|状态|悬停显示|
|---|---|
|待设价|`yyyy-MM-dd 下发 · 门店主数据`（数据来源）|
|已设价|包装单位（未填时显示"未填包装单位"）+ 第二行：产地 · 别名 N（均未填时显示"未填产地"）|
|临时停售|停售原因（琥珀加粗）+ 第二行：停售时间 · 补充说明|
|已失效|失效类型 · 日期 + 第二行：仍有 N 行未完成订单，照常发货 / 门店已重新上架 · 数据直接复用后自动恢复 / 门店备注|

> 包装单位、产地改成选填后可能为空，提示文案要**逐段拼接**，不能留下「 · 别名 xxx」这种前后都空着的残句——那比不显示更难看。

**FR-B03-7 每行的操作**

|状态|操作|
|---|---|
|待设价|「设价」（主链接）·「停售」（次要链接）|
|已设价|「编辑」（主链接）·「停售」（次要链接）|
|临时停售|「恢复在售」（主链接）·「编辑」（次要链接）|
|已失效|灰字不可点：「等待门店上架」；门店已重新上架时显示「等待恢复」|

行底色：待设价用浅色底标出；临时停售与已失效用灰调底——但**不改变文字颜色层级**，仍然是可读的正文色。

**FR-B03-8 已失效 Tab 的顶部说明**

当「已失效」Tab 中存在"门店已重新上架"或"仍有未完成订单"的货品时，列表上方显示一条 warn 横幅：

- `N 个货品门店已重新上架 —— 数据直接复用后会自动恢复，不需要你确认` + 说明"恢复后按失效前状态还原（已设价的仍是已设价，停售的仍是停售）。无需任何手动刷新。"
- `有 N 个 SKU 仍有未完成订单：失效只停「未来」，已经答应的货照常分拣、照常发货。`

**FR-B03-9 数据来源与异常**

|项|规则|
|---|---|
|数据来源|直接复用门店分配给本供应商的 SKU；供应端不落地全量主数据，只在一张扩展表上维护价格与扩展信息（BR-19）|
|同步状态|本页不展示任何「推送 / 同步」状态，也不提供手动刷新入口；门店 SKU 直接可用，无推送积压、无对账按钮（V1.0.1 起取消推送机制与手动刷新）|
|门店删除的 SKU|**不进任何 Tab**（连「全部」也不进），只在页头与底部汇总条报一个数（BR-20）|
|编码处理|门店下发的商品编码与 SKU 编码按原值保存与展示，不校验、不改写、不截断、不告警阻断（EC-15）|
|只读边界|本页对门店主数据**没有任何写操作**：不提供新增、编辑、删除、字段匹配入口，也没有"申请修改"通道。页面上唯一的写动作是设价、停售与导入，改的都是**供应商自己的记录**（货品价格与扩展信息）；V4.3 的「导入」不得新增 / 删除 SKU，也不得改商品名、规格、单位、形态、分类、品牌、门店 —— 这些字段门店发什么就是什么。V4.4 起导入模板第 2 列刻意把`品名 · 规格 · 门店`摆出来给人看，但**这一列上的任何修改都不会被上传**（Q-15）—— 看得见不等于改得动|

**FR-B03-10 底部汇总条**

左侧：`N 个 SKU · M 个商品 [· 另有 D 个门店已删除，不显示]`；中间：当前 Tab 的提示语（FR-B03-4）；右侧：分页控件（10 / 20 / 50）。

**FR-B03-11 导入货品信息（B03i）**

**为什么要有它。** 门店一次会推来几十个「待设价」SKU，而价格早就躺在供应商自己的报价表里。一个一个点「设价」意味着几十次跳页、几十次复制粘贴，而这些数本来就已经在文件里了。批量导入是唯一能把这件事压成一次操作的路径；**但它只替代"重复劳动"，不降低任何门槛** —— 价格仍然必填，仍然 > 0。

**入口。** B03 页头的「导入」（在「导出」左侧）。B03i 是操作页，不进侧栏。

**三步，一步都不能省：**

|步|用户在这里做什么|界面要点|
|---|---|---|
|① 提供数据|统一**选择表格文件上传**（.xlsx / .xls / .csv / .tsv），不再支持粘贴文本校验；也可先「下载模板」（.xlsx，SKU 与商品信息列已标红锁定、价格列标注必填）|顶部一条 info 横幅写清三条硬规则；右侧一张「九列怎么写」表，逐列给出必填性与"留空时怎么办"，其中第 1、2 列标红并标注「不可修改」、第 3 列标红并标注「必填」|
|② 校验预览|逐行看到"会写什么、会不会被挡"，可逐行取消勾选|四张数字（可写入 / 不写入 / 价格有变 / 待设价→已设价）；「可写入」表默认全选；「不写入」表逐行给原因，拒绝与无变化用两种徽标区分|
|③ 写入结果|看这一批到底写进去了什么，再决定回列表还是再导一批|结论横幅（含"停售中，恢复在售后新价才生效"）、写入明细表（价格变动 / 扩展信息 / 是否产生价格记录）、被挡明细可导出|

**列定义（9 列，列序固定）**

|#|列|必填|留空时|
|---|---|---|---|
|1|SKU 编码（标红 · 不可修改）|必填|整行拒绝（认不出是哪条货）；列头标红并标注「不可修改」，由系统预填，不可手改|
|2|**商品信息（标红 · 不可修改）**|— 不参与校验|不影响任何结果（这一列只给眼睛看，见下节）；列头标红并标注「不可修改」，模板中由系统锁定|
|3|货品价格（标红 · 必填）|必填，且必须 > 0|整行拒绝（BR-05 不打折）|
|4|包装单位|选填|保持原值|
|5|产地|选填|保持原值|
|6|保质期|选填|保持原值|
|7|别名|选填|保持原值|
|8|三方编码|选填|保持原值|
|9|备注|选填|保持原值|

**第 2 列「商品信息（只读）」：让眼睛认得出，但不让手改得动**

模板的扩展字段大多是空的，一行打开来只有一个 8 位 SKU 编码和一个价格（`S1001401,,18.50,,,,,,`）。供应商拿着 44 行文件核账时，这一行是菠菜还是西兰花，只能靠记编码。所以第 2 列放一份 `品名 · 规格 · 门店` 的拼接串（例：`菠菜 · 500g/袋 · 徐汇滨江店`），**只作对照，不参与导入**。

这条边界必须钉死，否则它会变成一个后门：

|用户可能做的事|系统的反应|
|---|---|
|拿它核账、找人确认"是不是这条货"|正常，这就是它存在的理由|
|在模板里把它改成别的品名|**不报错、不提示错误、照常导入，但改的那个字一个也不会写进去**；第 2 步汇总条与第 3 步结论横幅各留一句"「商品信息」列有 N 行与系统不一致，已忽略 —— 这一列不上传"|
|整列删掉（只留 8 列）|照样能导，解析结果与带它时完全一致|
|想把品名 / 规格 / 门店改对|B03i 不提供这条路：这三项是**门店主数据**，由门店维护，供应端改不了（FR-B03-9 只读边界）。要改只能让门店改|

为什么不干脆做成"改了能上传"的申请修改通道：商品名与规格一旦可被供应端改写，同一家门店的两个供应商会把同一条货写成两个名字，报价单、分拣单、对账单上的品名从此各说各话。所以这里的选择是——**给足辨认的信息，但不给写入的入口**。

一个实现约束（给研发）：识别表头失败时按**列数**分流——9 列按当前列序读，8 列按上一版列序读。这样用户删掉表头后，旧文件的价格不会被读到包装单位上；只读列在这一步整列跳过，不进入任何字段映射。

**三条硬规则（少一条都会把已经设好的货弄坏）**

1. **价格必填且 > 0。** 货品价格是唯一流进报价 → 订单 → 对账的数字，导入不能绕过它。已设价的行不会因此被逼着重打一遍：模板已经预填现价，你只改要改的格。
2. **只收待设价 / 已设价 / 临时停售。** 已失效（门店下架）与门店已删除是只读留痕，一律挡回，并在「不写入」表里逐行给理由。导入不改状态：待设价填了价自然变已设价，停售的仍是停售。
3. **空单元格 = 保持原值。** 这是本功能最容易做错的一条。如果"空"被当成"清空"，那么一份只填了价格的文件会把所有别名、产地、保质期、备注全部抹掉 —— 而用户的本意只是设个价。要清空某个字段，去 B02 货品编辑里删（B03i 不提供"清空"语义）。

**逐行校验与拒绝理由**

|情况|结果|文案示例|
|---|---|---|
|SKU 编码为空|拒绝|缺 SKU 编码|
|SKU 不在自己的门店商品里|拒绝|`SKU「S1005001」不在你的门店商品里`|
|门店已删除|拒绝|门店已删除 · 已逻辑删除，只读留痕|
|已失效（门店下架）|拒绝|已失效（门店下架）· 只读留痕，等门店重新上架|
|价格为空|拒绝|价格必填|
|价格非数字或 ≤ 0|拒绝|`价格须为大于 0 的数字（现填「面议」）`|
|同一 SKU 在文件里出现多次|首行有效，其余拒绝|`与第 2 行重复，只认第一行`|
|字段超长（包装 / 产地 / 保质期 / 别名 / 三方编码 / 备注 分别为 20/20/16/20/30/100 字）|拒绝|`包装单位 超过 20 字（现 22 字）`|
|「商品信息（只读）」列与系统不一致|**忽略，不拒绝**（与"能否写入"无关）|`「商品信息」列有 N 行与系统不一致，已忽略 —— 这一列不上传`|
|校验通过但一个字段都不会变|不进"可写入"|与现有信息完全一致，没有要写的东西|

> 行号一律按**用户文件里的行号**报（表头算第 1 行）。报"第 7 行"而不是"第 3 条"，用户才能照着改。

**写入规则（与 B02 单条保存同源）**

- 单条保存与批量导入走**同一个写入函数**：改价必留痕（价格历史 +1 条）、未提交报价单里该行的初始价跟着变（BR-07）、`已设价` 由价格 > 0 派生。两条路分开写，必然出现"单条记了历史、批量没记"或"一边同步了报价价、另一边没同步"。
- 操作人记为「批量导入」，价格历史里可区分是手改的还是导进来的。
- 写入在**同一批内逐行独立**：某一行失败不影响其余行（EC-31）。
- 结果页落点：见 4.3 落点规则（全已设价 → 已设价 Tab；混有停售 → 全部 Tab）。

**导入记录（V1.0.1 新增）**

每次导入（无论成功 / 失败 / 无变化）都会留一条记录；B03i 页面底部不再内联明细，改为**单一入口 → 列表页 → 详情页**：

- **入口**：B03i 页头「导入记录（N）」按钮，N 为记录条数，点进独立的「导入记录」列表页。
- **列表页**：按时间倒序列出每次导入的 时间 / 操作员 / 成功数 / 失败数 / 无变化数，点任意一行进入详情。
- **详情页**：左右两栏分别展示该次导入的**成功改动明细**（SKU · 品名 · 门店 · 价格变动 · 变更字段）与**失败原因**（行号 · SKU · 品名 · 门店 · 被挡回理由）。
- **持久化**：记录用 localStorage 存储，关页再开仍在；该列表页**不进左侧导航**，只从 B03i 入口进入（与 B02 / B03i 同一处理：详情 / 操作页不出现在导航里）。

**边界与不做**

- 单次上限 **500 行**，超出部分忽略并在界面报出被忽略的行数；再大的量应当走接口对接，不是粘贴。
- 表头可有可无：有表头按列名对，没有就按模板列序读（不能因为删了表头就把整份文件判废）；无表头时按列数分流——9 列按 V4.4 列序、8 列按 V4.3 列序，避免旧文件的价格读到包装单位上。分隔符支持逗号与制表符，支持双引号包裹（文件解析层面）。
- **不做**：字段映射 / 列序自定义、导入时新增或删除 SKU、导入改商品名规格等单位分类（FR-B03-9 只读边界；模板第 1、2 列因此只读不写）、导入写"停售 / 失效 / 删除"这类状态、导入清空字段（见硬规则 3）。<br>（V1.0.1 起已支持 .xlsx / .xls 二进制直传解析，并接入 ExcelJS 生成带红字锁定列与必填标注的真实 .xlsx 模板，无需再另存为 CSV。）

**FR-B03-12 已设价标签批量停售（V1.0.1 新增）**

在「已设价」标签下，工具栏右侧提供「批量停售」按钮，可一键停售**当前筛选条件下**的全部已设价货品。

- **触发位置**：仅当处于「已设价」标签时显示；按钮文案为「批量停售 · N 个」，N = 当前筛选条件下已设价货品数（实时随筛选变化）。
- **范围语义（全量，非当前页）**：停售范围是**当前筛选条件下的全部已设价货品**，不限于列表当前页；分页只影响展示，不影响批量范围。已处于停售的货品跳过并在结果中提示。
- **确认弹窗**：点击后弹出确认框，须填写停售原因（必填，同 BR-13 选项），补充说明选填；确认后逐条写入停售记录（SUSPEND）。
- **落点**：完成后自动跳到「临时停售」标签，可立即看到刚停售的货品；其余标签计数同步更新（BR-21 口径现算）。
- **与单行停售同源**：与 FR-B03-7 每行的「停售」走同一套原因选项与写入逻辑，差异仅在"一次处理一批"。

## 7.2 B02 货品编辑

**FR-B02-1 页面目标与入口**

维护单个货品的价格与选填信息，是"从待设价走到已设价"的唯一入口，也是改价、**改货品别名**的唯一入口。入口（V4.1 起只有 B03 一处，共三种状态的行）：

|进哪一行|行上的动作|进去之后|
|---|---|---|
|B03「待设价」|设价|主按钮「保存并设价」，页头挂待设价说明横幅|
|B03「已设价」|编辑|主按钮「保存修改」|
|B03「临时停售」|编辑|主按钮「保存修改」，页头标「已停售」，右下角按钮变「恢复在售」|

「已失效」的行**没有编辑入口**（只读留痕，等门店重新上架后自动恢复），因此 B02 不会被从已失效行打开。

**FR-B02-2 页面标题**

- H1 固定为**「货品编辑」**，不是货品名。编辑型页面的标题回答"你在做什么"，"货品是谁"放在副标题里说清楚——和「报价单编辑」「创建发货单」同一套命名。
- 副标题：`[已停售 · ] 货品别名（门店品名 商品名） · SKU 编码 · 门店 · 状态`。别名与门店品名相同时不重复显示括注。
- 右上按钮：`返回` + 主按钮（待设价时文案为「保存并设价」，已设价时文案为「保存修改」）。
- 右上状态标签：有不达标字段时「缺 X 项 · 未保存」（琥珀），全部达标时「填写完整 · 可保存」（绿）。

**FR-B02-3 页面构成**

单列主卡自上而下三段：只读的**货品基础信息**（9 项）、可编辑的**扩展信息**（7 项，分三行）、右栏一张辅助卡「这段时间不卖这个货」。底部不需要固定操作条，主按钮在页头。

**FR-B02-4 只读区：门店定义，不可编辑**

以"标签 + 值"的描述形式呈现，**不显示输入框——没有输入框，就说明不用填**。顺序固定为：

|#|项|内容|
|---|---|---|
|1|商品名称|门店主数据中的名称（只读）|
|2|商品编码|等宽展示|
|3|SKU 编码|等宽展示|
|4|商品形态|形态标签 + 括注验收口径（毛菜·验收按扣重 / 净菜·验收按实收 / 半成品·验收按成品率）|
|5|商品分类|原样展示|
|6|品牌|原样展示|
|7|下发门店|门店名|
|8|销售规格|门店定义的规格|
|9|单位|门店定义的单位|

只读区下方，若同一商品下还有其他 SKU，插入一条提示：

> **同一个商品还有 N 个 SKU**：S1001302 2.5kg/箱（徐汇滨江店 · 待设价）。**同物不同规格，必须分别设价** —— 它们的货品价格不一样，合并成一个会直接算错钱。

**FR-B02-5 可编辑区：扩展信息（7 项，三行）**

|行|字段|必填|占位示例与提示|
|---|---|---|---|
|1|**货品价格**|**是（唯一）**|占位"如 3.20"；提示"元/件 · **唯一必填项，须 > 0** · 报价、直采都取这个价；填完保存即变「已设价」"|
|1|货品别名|否|占位"如 青菜 / 洋山芋（留空则全按门店品名）"；提示"出现在拣货单、库位标签、仓库检索框"|
|1|货品第三方编码|否|占位"如 供应商自有 SKU 码 / 条码"|
|2|包装单位|否|占位"如 周转箱 · 5kg/件"；提示"**选填** · 验收时和门店包规核对的依据，不填也能供货"|
|2|产地|否|占位"如 上海崇明"；提示"**选填** · 填了会印在送货单与溯源标签上"|
|2|保质期|否|占位"如 2 天"；提示"选填 · 影响配送批次建议"|
|3|内部备注|否|占位"如：叶片完整、无黄叶，单株 250g 左右"；**跨整行（3 列宽）**；提示"选填 · 只有你自己看得到，不打印在任何单据上"|

排序理由（评审时会被问，直接写在这里）：**要填的先出现**。价格和别名是日常改得最勤的两项，排在第一行；包装、产地、保质期是设价时顺手补的，第二行；内部备注只给自己看，放最后一行跨列。

必填星号**全页只有一个**，在「货品价格」上。这是 BR-05 在界面上的唯一体现——星号数量本身就是一种承诺，星号越多，用户越会怀疑"是不是又得先补一堆才能给价"。

**FR-B02-6 待设价态的页头横幅**

当货品处于待设价时，页头下方插入一条 info 横幅：

> **门店分配过来就是「待设价」—— 填完货品价格，保存即设价**  
> 这一页**只有货品价格是必填**（没有价格进不了询价单）；包装单位、产地、保质期等其余字段可以先留空，回头补也不影响供货。  
> 保存成功后这个 SKU 直接变成「已设价」，参与询价、直采与发货，**不需要再做任何确认**。

**FR-B02-7 交互规则**

本页**不落库草稿**：不提供"先存一半"，也不做字段失焦自动保存。用户本次会话内未保存的修改会保留在内存里（校验被拦下后重渲染不丢内容），刷新页面即作废。任何修改都在点主按钮时一次性提交。

1. 点保存时由前端校验（清单见 FR-B02-8），任一项不合规即标红拦截，**请求不发出**。页面重渲染后自动聚焦第一个出错的字段，并弹出汇总提示："有 X 项不符合要求，未保存：货品价格"。
    
2. 校验通过才提交；提交成功后一次性写入全部字段，然后回 **B03**。列表只有这一个来源，所以"回哪一屏"没有歧义；**但 Tab 要按保存后的状态重算**（见 4.3 落点规则）—— 停售中的货品改完仍在停售，就必须回「临时停售」，不能因为"这次点了保存"就当成已设价。
    
3. 价格发生变更时额外触发两件事：写一条价格变更记录；同步更新该 SKU 在**尚未提交**的报价单里的初始价。已提交的报价单与已生成的订单不动（BR-07）。
    
4. 保存成功提示**按保存前的状态分四种**，不能一句"已设价"包打天下：
    
    |保存前的状态|提示|
    |---|---|
    |待设价|`已设价 ¥3.20 · 价格变动已记入历史 · 状态转为「已设价」，可参与询价与直采`|
    |已设价，价格有变|`已改价 ¥3.20 · 价格变动已记入历史 · 只影响从这一刻起的新单`|
    |已设价，价格未变（只改了别名 / 包装等）|`已保存 · 价格未变，未产生新的价格记录`|
    |临时停售中|`已保存 · 该货品仍在临时停售中，恢复在售后新价才生效`|
    
    最后一行是必须单独写的：停售中的货品保存完**并没有**"转为已设价"，它仍停售、仍不进询价；照着第一行喊，等于告诉用户一件没发生的事。
    

**FR-B02-8 本页的标红清单**

标红规则按 BR-18 执行。**只有货品价格会拦人**：

|情形|页面表现|
|---|---|
|货品价格为空|输入框标红，下方"货品价格必填 —— 没有价格，这个货品进不了询价单，也开不了直采单"|
|填了负号|"货品价格不能为负数"|
|填非数字（含"元"、单位、空格）|"只能填数字（如 3.20），不要带「元」、单位或空格"|
|填 0|"货品价格必须大于 0"|
|大于 9999|"单价 xxxx 元明显偏高，疑似多输了一位数"|
|超过两位小数|"最多 2 位小数 —— 金额只精确到分"|
|较均价偏离超过 ±50%|拦截并说明："较**近 3 个月**均价 ¥x.xx 偏离 ±N%，超出 ±50% 预警线；确实要调这个幅度，请走『批量调货品价格』（带留痕）"。**文案里的口径必须是实际用的那一档**（默认近 3 个月，用户改过就跟着改）；该口径内无改价记录时，算不出均价，这条预警直接跳过|

包装单位、产地、保质期、别名、第三方编码、备注**不做任何校验**：它们是文字，写「周转箱」还是「泡沫箱」不影响算钱，拦下来只会让用户为了一个空格或错别字反复重填。填错了改完保存即可，历史单据不受影响。

标红用平台的错误色，与列表里 `—`、"待设价"这类状态色区分开——后者表示数据状态，前者表示本次填写不合规，两者不能视觉混淆。

**FR-B02-9 辅助卡「这段时间不卖这个货」**

这是"不卖"的**设置入口**。卡片文案固定说明三件事：停售期间不进新询价、不排分拣；已提交的报价与在途订单照常履约；想再卖点「恢复在售」即可，记录一直都在。

按钮：当前是临时停售时显示「恢复在售」，否则显示「临时停售」。点「临时停售」打开弹窗：

- 顶部灰底摘要：`商品名 · 规格 · 门店`，并说明"停售期间它不进新的询价单，已提交的报价、已生成的订单照常履约；随时可以恢复在售，记录一直都在"。
- 字段：「为什么停售」（必选，见 BR-13）、「补充说明」（选填，200 字以内，提示"只有你自己和运营看得到，不会出现在任何单据上"）。
- 按钮：取消 / 确认停售。确认后刷新页面，并提示"已临时停售 · 随时可以恢复在售，不删任何记录"。

> 这一段不能只写在文档里。已设价的货品往往连着在途订单，供应商若不确定"停售之后手上的单子会不会断"，就会一直拖着不用，问题拖到分拣和验收才暴露。

## 7.3 B06 货品价格趋势

**FR-B06-1 页面目标与入口**

提供价格的历史追溯与定价参考。**它是记录，不是定价来源**——定价来源是货品编辑页里的货品价格与报价时的单价。入口：侧栏、批量调价提交后的返回页。

**FR-B06-2 页面构成**

列表 + 明细弹层。任何改价行为都发生在货品编辑或批量调价，本页只负责让价格可追溯。

**FR-B06-3 列表**

只展示**有货品价格、且未被门店下架 / 删除**的货品。共 10 列：SKU 编码 / 门店 / 品名 / 规格 / 当前货品价 / 均价估算 / 偏离 / 变更次数 / 最近变更 / 操作（趋势）。

- **均价估算列是两行**：主值是 `¥x.xx`，下面一行小字写 `n/N 次` —— n 是当前口径内的样本数，N 是这个货品的全部变更次数。一眼能看出"这个均价是用几条记录算的"，而不是只给一个孤零零的数（口径见 FR-B06-7）。
- **口径内一条记录都没有时，均价与偏离都显示 `—`**，不回退到全部历史。此时筛选条右侧会点名"另有 M 个货品此口径内无记录"。
- 偏离 =（当前价 − 均价）÷ 均价 × 100%，保留一位小数，带正负号。高于 +5% 标琥珀，低于 −5% 标绿，其余中性灰。均价为 `—` 时偏离同样是 `—`（不能写 `+0.0%`，那读起来像"跟均价持平"）。
- 临时停售的货品**仍然在列表里**：停售停的是"卖不卖"，不是"价格历史没了"。
- 待设价、已失效、门店已删除的货品不进列表；页脚在存在这类货品时提示"另有 N 个未设有货品价格，未计入"。
- 页脚右侧固定说明："所有变更留痕，对账争议时可举证。"
- 筛选条右侧写明当前口径（`均价 = 近 3 个月内变更价的简单平均`）并带一个「改范围」按钮，同一个入口也在页头（`均价口径 · 近 3 个月`）。**两处都能改，但只有一个配置值**。

**FR-B06-4 明细弹层（含趋势折线图）**

标题「货品价格趋势 · 商品名」。自上而下四段：

1. **头部四格**：SKU 编码 / 当前货品价 / 均价估算 / 变更次数。均价估算下方小字标注 `${口径} · n/N 次计入`。
2. **趋势折线图**（规格见 FR-B06-5）。
3. **提示条**：「均价 = **「近 3 个月」内 5 次**变更价的简单平均（这一共 12 次变更，只有口径内的计入），仅作**定价参考**。要换时间范围，回列表点「均价口径」。下单以『提交时刻的货品价格』为准，此处改价不影响已在途 / 已生成的订单。」
    - 口径内无记录时，提示条改为醒目样式并写明：「**「近 3 个月」内没有一条改价记录**，所以均价算不出来 —— 这个货最后一次改价是 2026-04-24。它多半是长期不调价的稳定品；要看均价，把口径放宽到「全部历史」，或等下一次调价后自然就有了。」
4. **变更明细表**：按时间倒序，列为 变更日期 / 操作人 / 价格 / 对均价偏离 / **是否计入均价**（口径内标「计入」绿标，口径外写「口径外」灰字，整行底色略灰）/ **操作**（标记异常 / 取消标记）。表头右侧注明"与上图同一个数据源 · 灰字行在口径外，不参与均价"。

> 明细表**列全部历史**、只标注哪些计入，而不是只显示口径内的行。原因：用户需要知道"这个货一共改过几次"，也需要看到被筛掉的是哪几次 —— 藏起来就等于让均价无法核对。

**异常标记（V1.0.1 新增）**：每条改价记录均可标记 / 取消「异常」。被标记的记录以**最高优先级**排除出均价及所有统计——它优先于时间口径：即便落在口径内，只要被标异常就照样踢出，不参与均值（`priceAvg` 改走 `histStat`：取「口径内 且 非异常」的样本求简单平均）。该标记按 `sid + 日期｜价格` 持久化到 localStorage，刷新后仍在。

- 明细表：异常行整行淡红底，状态列显示红字「异常排除」，偏离列显示「异常」；其余按原口径显示「计入 / 口径外」。
- 趋势图：异常点用红色空心圆标出，悬停提示框标注「否 · 异常」，图例补充「异常调价 · 已排除」。
- 一处改动、全站联动：B06 列表的均价 / 偏离、趋势详情的均价与偏离、B02 保存时的 ±50% 偏离预警，全部自动排除异常记录（详见 FR-B06-7 作用域）。

弹层为宽版，只读——**不提供任何编辑控件**。底部只有「关闭」。

**FR-B06-5 趋势折线图规格**

三条设计约束决定了它长什么样：

**① 横轴 = 设价时间，按真实天数分布。** 点的横向位置按两次设价之间的**实际天差**换算，**不是等距排开**。等距会把"一个月改 5 次"和"一年改 5 次"画成一模一样的形状——而这两件事的含义正好相反。

**② 纵轴 = 价格，自适应，不固定从 0 起。** 生鲜单价从 1.85 到 28.00 差十几倍；固定从 0 起画，低价货的线会被压成一条贴着轴的平线，波动一点也看不出来。做法：取数据（含均价）的上下界，各留 **18% 余量**；下界不小于 0。

**③ 刻度 3–6 格。** 从一组"人眼好读"的候选步长（0.01 / 0.02 / 0.05 / 0.1 / 0.2 / 0.25 / 0.5 / 1 / 2 / 2.5 / 5 / 10 / 20 / 25 / 50 / 100 / 200）里挑第一个能落下 3–6 格的步长。判据不能是"格数 ≤ 5"：单价 1.85 的货波动只有两毛，那样挑会只剩 2 格刻度（¥1.85 / ¥1.90），轴上什么都读不出来。

**元素与交互**

|元素|规格|
|---|---|
|网格与纵轴刻度|水平网格线 + 左侧价格标签（`¥x.xx`，右对齐）|
|轴标题|左上「价格」，右下「设价时间 →」|
|**口径分段（V4.5）**|**口径内**：绿色 2.2px 实线 + 折线下方渐变面积。**口径外**：浅灰 1.4px 虚线（`4 4`）+ 空心点。分界处画一道灰色竖虚线。整段都在口径外时，全段走虚线、不铺面积、不画均价线 —— 但**线一定画出来**，否则看起来像数据丢了|
|面积填充|折线下方渐变填充（顶部 16% 透明绿到 0），强调"这是一条价格走势"而非一条裸线。**只铺口径内那一段**|
|折线|绿色 2.2px，圆角连接；口径外那一段单独一条浅灰虚线|
|数据点|白底绿描边圆点，半径 3.6px；口径外空心灰点；**最后一个点**半径 5px，并在点的上方/左侧标注「当前 ¥x.xx」（贴近右边界时改右对齐贴在点的左侧，否则会溢出画布）|
|均价参考线|琥珀色虚线（5 4 虚线）+ 标签「均价 ¥x.xx」。标签默认贴右端；若最后一个数据点正落在均价线附近（纵向差 < 18px），标签改贴左端，避免与「当前 ¥x.xx」撞在一起。**口径内无样本时不画这条线**（算不出来就不画，不画一条 0 或者猜的值）|
|悬停竖线|指向该点的竖直虚线|
|悬停提示框|见下|
|横轴日期标签|显示 `MM-DD`；相邻标签横向间距不足 56px 时抽稀；**首尾一定保留**（那是"从哪到哪"）；贴边时改锚点，避免标签被画出画布|
|空态|只有 1 条价格记录时不画图，显示"这个货品只有 1 条价格记录，还画不出趋势 —— 改过一次价之后，这里就有曲线了。"|

**悬停提示框**

- 尺寸 186 × **124**，位置默认在点的右上方；**靠右则翻到点的左边，靠顶则翻到点的下方，下方也放不下则夹进画布**——弹层里被裁掉的提示等于没有提示。
- 内容：`第 i 次设价 · 共 N 次` / 设价日期 / 操作人 / 价格（加粗）/ 对均价偏离（带正负号；高于均价琥珀、低于均价绿、持平灰；**均价算不出来时写 `—`**）/ **是否计入均价**（是 / 否 · 口径外）。
- 命中区是 15px 半径的透明圆，比可见圆点大得多——不然鼠标要精确到像素才碰得到。
- 显隐用纯 CSS 悬停，不挂 JS 事件：弹层反复重绘不会留下失效监听。

**图下图例**：「货品价格」（实线）/「均价估算 ¥x.xx」（虚线）/ 有口径外记录时再加一项「口径外 · 不计入均价」（浅灰虚线）；右侧提示写当前口径与计入比例，如"口径 近 3 个月（08-01 起）· 12 次里 5 次计入 · 悬停看单点明细"。

**FR-B06-6 价格历史的形态**

- 每个货品的历史记录为 **8–14 条**，覆盖 5 个月到 1 年多（跨度 150–500 天）。**间隔越往前越大**：最近一次改价隔 7–16 天，最远一次隔 40–50 天 —— 同一条历史因此"近期密、远期疏"。
    - 若各段等距，跨 400 天就得塞进 40 个点，图上挤成一团；而"近期密、远期疏"恰好也是真实的改价节奏。
    - 这个形态是 V4.5 改的：V4.4 之前是 4–7 条、跨度 30–60 天、末点停在 2026-09 中旬，**「近 1 个月」这一档会把所有货品的样本取空**，配置看起来像坏了。
- **末点贴近今天**（1–13 天前，按 SKU 稳定派生），不是固定取某个历史日期。
- 约 **1/8 的货品是「长期没调过价的稳定货」**（米面油、调味干货这类），最后一次改价在 6–10 个月前。它们在「近 1 / 3 / 6 个月」里一条样本都没有——正好用来验证口径筛空之后页面长什么样。
- 约 **4 成的货品「最近正在密集调价」**（叶菜跟着行情走），最近三次间隔压到 3–9 天。不区分的话，所有货品在「近 1 个月」都只筛出 2 个样本，每一行都写着 `2/N` —— 看着像写死的数，也看不出这档口径到底筛掉了什么。
- 最后一个点严格等于当前货品价格。
- 单次波动幅度约 ±4.5%：波动太大，演示数据自己就会撞上"较均价偏离 ±50%"的校验线，用户什么都没做就先看到红字。
- **同一货品每次打开必须看到同一条曲线**（按 SKU 稳定派生）。若每次刷新形状都不一样，用户会以为价格真的变了——那比没有图更糟。
- 每次改价追加一条记录：日期为**当天（本地时区）**、操作人为当前账号（批量调价为「批量调价」）。

**FR-B06-7 均价的时间口径**

**为什么要它。** 原本的均价是"历次变更价的简单平均"—— 但这个"历次"没有边界。一条两年前的改价和上周的改价，在这个算式里权重一模一样。生鲜行情是按季度走的，一年前的价格对今天的定价参考价值接近于零；而供应商在核账时问的是"最近这个价位正常吗"，不是"史低价多少"。所以时间范围必须能被主动设定，而不是由数据多少决定。

**入口。** B06 页头 `均价口径 · 近 3 个月`（在导出左侧）；筛选条右侧另有一个「改范围」按钮（离数字更近，改完立刻能看到变化）。**两处打开的是同一个弹层、读写的同一个配置值。**

**五档口径**

|档位|取值区间|说明|
|---|---|---|
|近 1 个月|今天 −30 天 ~ 今天|看最近一轮行情|
|**近 3 个月（默认）**|今天 −90 天 ~ 今天|生鲜报价的常用参考窗口|
|近 6 个月|今天 −180 天 ~ 今天|跨淡旺季|
|近 12 个月|今天 −365 天 ~ 今天|看一年的价格带|
|全部历史|不限|等于 V4.4 及之前的行为|

弹层里每一档都实时给出**启用这一档的后果**：「N 个货品有样本 · 共 M 条」，以及"另有 K 个货品无记录，均价显示「—」"。**不下这个数，用户只能靠猜。**

**口径决定"取哪些样本"，不改变算法**

选完口径之后，样本仍然是**简单平均**：把区间内的记录取出来，加起来除以条数。没有加权、没有移动平均、没有"越近的越算数"。这一点必须写死在文档里 —— 一旦"时间范围"和"加权方式"混在一起，同一个数就有两种解释，谁也算不清。

**作用域：全站一处配置**

|用到均价的地方|跟着变吗|
|---|---|
|B06 列表的「均价估算」与「偏离」|是|
|B06 明细弹层的均价线、头部均价、逐条偏离|是|
|**B02 货品编辑保存时的 ±50% 偏离预警**|**是**|
|询价单里的"参考价"（当前货品价格）|**否** —— 那不是这个均价，是另一个口径的另一件事|

第三条最容易被漏掉：预警文案里必须带口径（`较近 3 个月均价 ¥18.50 偏离 +52%`），否则同一句话在两个口径下指的完全不是同一个数。**口径内无样本时，B02 的预警直接跳过**（算不出均价就没有偏离可言），这是合理降级，不是放水。

**口径内无样本：显示 `—`，不回退**

- B06 列表：均价 `—`、偏离 `—`，小字写 `0/N 次`。
- 明细弹层：头部均价 `—`；图上整段走虚线、不铺面积、不画均价线；提示条改为醒目样式并给出最后改价日期与出路（放宽口径 / 等下次调价）。
- **不回退到全部历史。** 一回退，这个设置就变成了摆设 —— 用户把它设成 1 个月，看到的却是一年的均价，然后以为配置没生效。算不出来就写算不出来。

**切换语义**

- 弹层里点选项只改**草案**，点「应用口径」才生效；「取消」或按 ESC 一律不生效。
- 应用后立刻重渲染当前页，并 toast 说明（`均价已改按「近 6 个月」计算 —— 全站均值同步`）。
- 口径是**用户级配置**（存在账号下，换浏览器仍是同一档），不是页面级的临时筛选。原型里用内存变量模拟，刷新回落默认「近 3 个月」。

**不做的**

- 不做自定义起止日期：五档够用，自由日期会让"这个均价是怎么算的"变成一件需要追问的事。
- 不做按货品 / 按门店的差异化口径：均价是横向比较用的，每行口径不同就没法比。
- 不做加权（按天数、按金额）：见上文"不改变算法"。

# 8.跨模块协作

  

|关联模块|交接内容|本模块的责任|交接不上时会怎样|
|---|---|---|---|
|门店商品系统（上游）|下发的门店商品与 SKU 主数据，含商品编码、SKU 编码与全部字段，由供应端直接复用（BR-19）|接收与透传：不生成编码、不改写、不校验修正|编码不规范照存照显（EC-15）；数据接入异常时供应端按现有数据展示，不提供刷新入口（EC-11）|

|分拣|拣货单显示货品别名与包装单位|保证别名可用；包装单位选填，缺了回退门店品名、不打印包规|别名缺失时回退使用门店商品名|

|经营看板|已设价覆盖率、设价及时率|提供可统计的状态数据|统计失败不影响主流程|
|角色权限|角色与门店范围|按角色控制功能可见与可操作|无权限时功能不可见、操作被拒绝|
|操作日志|设价、改价、停售、恢复、失效、删除等动作留痕|主动上报|日志失败不阻断业务，事后补录|

|缺货预告（A05b）|中标但部分行供应商侧缺货的预告|中标结果只负责"谁中标"，缺货由缺货预告承接|缺货行仍须履约或走缺货预告流程|
|待办中心（A03）|「询价待报价」页签 = 待报价数|与 C01 同口径，提交后自动离开待办|写死数字会两数不一|

# 9.异常与边界场景

|编号|场景|处理口径|
|---|---|---|
|EC-01|门店删除商品，但供应商仍有未完成订单|供应端逻辑删除（退出清单与全部 Tab），但**未完成订单继续分拣、发货、验收、结算**。历史单据仍可追溯到该 SKU 的名称与规格|
|EC-02|门店修改了某个 SKU 的销售规格|**SKU 编码不变**。只更新规格的内容，不新建 SKU，历史报价单、订单、对账单的引用全部保持有效，不断链。供应商已填的价格、包装单位、产地、别名原样保留（复核提醒能力为 P1，编码不变本身是强制规则）|
|EC-03|同一商品在多家门店各有一个 SKU|视为各自独立的供货关系，价格与包装分别维护，互不联动|
|EC-04|两个账号同时改同一条货品的价格|后提交的收到"已被其他人修改，请刷新后重试"，不覆盖对方数据|
|EC-05|批量调价中途失败|给出成功与失败明细，失败项保持原价，可重试；不出现"部分写入却没有记录"的情况|
|EC-06|调整后价格小于等于 0|提交前阻断，并列出违规 SKU|
|EC-07|分配过来长期不设价|一直计入 B03 待办与侧栏徽标，不会自动消失。第 7 天、第 15 天发出提醒（提醒能力为 P1）|
|EC-08|门店重新上架，但供应商不想恢复在售|不做人工确认，状态按失效前还原。若失效前是停售，恢复后仍是停售；若失效前在售而现在不想卖，再点一次「临时停售」即可|
|EC-09|两个 SKU 用了同一个别名|允许保存，保存时提示"该别名已被 N 个货品使用"，拣货单需以 SKU 区分|
|EC-10|价格显著偏离自己的历史均价（超过 ±50%）|保存时拦截，说明偏离幅度，并提示走批量调价（带留痕）。理由见 FR-B02-8|
|EC-11|门店 SKU 数据接入异常 / 不可用|直接复用门店 SKU 失败时，页面按当前已有的扩展表与门店数据展示，不伪造或缓存过期数据；本页不提供刷新入口，异常由接入层提示（BR-19）|
|EC-12|门店整条品类下线|该品类全部 SKU 一起转为已失效，在「已失效」Tab 内按商品聚合说明，不逐个弹窗|
|EC-13|账号的门店范围变更，导致看不到原有货品|列表按新范围过滤，数据不删除；范围恢复后重新可见|
|EC-14|供应商切换经营主体（多企业）|全部数据按主体隔离，切换即换一套数据，不混合展示|
|EC-15|门店下发的编码不符合平台"惯例"（前缀不同、超长、含特殊字符），或上游整体变更了编码规则|按原值保存与展示，不校验、不改写、不截断、不告警阻断。编码规则的解释权在门店系统|
|EC-16|同一次门店数据变更中，同一个 SKU 编码出现两条冲突记录|以变更顺序的最后一条为准，覆盖前一条；不合并、不挑"更完整"的那条，也不产生两条供货关系|
|EC-17|对已设价、且有在途报价与订单的货品临时停售|**允许操作**。停售后该货品不再进入新的询价单；已提交的报价单、已中标的订单、已生成的送货单按原货品信息继续履约，不因停售被拦截、被改价或要求重新确认；已填的扩展信息保留（BR-12）|
|EC-18|包装单位 / 产地为空，但货品已设价|**属于正常状态，不拦截任何流程**（BR-05）。列表与单据该处留空；B03 状态悬停显示"未填包装单位""未填产地"；直到供应商自己补上|
|EC-19|货品只有 1 条价格记录（从未改过价）|变更次数显示 1；明细弹层不画图，显示空态说明"只有 1 条记录，改过一次价之后就有曲线了"|
|EC-20|价格点很多（改价频繁），横轴标签挤不下|标签抽稀（相邻间距 < 56px 时省略中间标签），**首尾一定保留**；靠近画布边缘的标签改锚点，不允许半个字被裁掉|
|EC-21|悬停提示框靠近画布边缘|右侧放不下翻到点的左侧；顶部放不下翻到点下方；下方也放不下则夹进画布内。不允许出现被弹层裁掉一半的提示框|
|EC-22|门店删除后，同一个 SKU 编码又被分配给本供应商|视为新的供货关系，按当前数据重新落成「待设价」；原逻辑删除记录保留在日志中，不恢复旧价格|
|EC-23|已报价但截止前想改|进 C03 改，以最后一次提交为准；无需撤回旧单（BR-26）|
|EC-24|未参与（从未提交）的询价单|无报价单入口；C06 渲染"无报价数据"提示；C07 无数据可看|
|EC-25|待公示想看结果|「看中标结果」灰置；C07 守卫页提示"待门店确认后公示"|
|EC-26|报价行含「不可供」|不填价、不计入报价合计、不进比价；C06 标"本轮未报价"|
|EC-27|询价单里出现待设价 SKU|不允许：询价只含已设价货品（BR-24）；若门店误推，按商品与价格模块规则应先设价|
|EC-28|部分行缺货|中标结果照常出；缺货由缺货预告（A05b）承接，不影响"谁中标"的结论|
|EC-29|提交时部分行未填价|前端标红拦截，提示"第 X 行还没填报价价（或改选不可供）"，请求不发出（BR-18 同源）|
|EC-30|同一次提交覆盖上一次|仅保留最后一次提交的快照；历史提交不留存、不追溯|
|EC-31|批量导入中途有一行失败（数据已被别人改过、字段超长等）|**同一批内逐行独立**：该行保持原值并在结果页列为被挡，其余行照常写入；结果页分列"成功 / 被挡 / 无变化"，不出现"写了一半却没有记录"（与 EC-05 同口径）|
|EC-32|导入文件里的 SKU 已被门店下架 / 删除|一律挡回并给理由，**不静默跳过**。被挡的行一个字段都不写，也不产生价格历史；用户改完文件可再导一次|
