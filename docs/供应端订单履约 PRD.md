# 1. 背景与目标

## 1.1 业务背景

平台服务的是“食堂 / 餐厅采购 + 生鲜供应商履约”的场景。订单履约是交易链的中段：询价报价产生中标订单，门店直采产生直采订单，供应商接单后完成备货、发货、验收核对、售后处理与结算对账。

链路上有两类主体：

**门店（采购方）** 维护商品、SKU、采购计划与订单；门店下单只到**配送日期**，验收结论、拒收、退货由门店侧录入并回写供应端。

**供应商** 不新建订单、不改量、不议价；核心动作是把订单承诺落成实际出库，按实际到店验收结果确认结算依据，并对门店发起的退货申请做出处理。

订单履约的产出被下游直接消费：

|消费方|消费内容|缺失后果|
|---|---|---|
|备货参考|按备货日聚合的商品需求量与已预告缺口|备货靠逐单翻找，容易少备或重复备|
|发货管理|系统自动生成的待发货单、实发量与差异备注|无法确认发货、无法生成送货单|
|验收与售后|发货行快照、冻结数量与备注|验收无核对依据、差异无法归因|
|结算对账|验收合格量、已通过退货量、下单单价|对账金额不可验算、争议无法追溯|
|食安合规|报告引用与发货日期有效期匹配|报告未关联或关联错误，合规材料断链|

# 2. 角色与场景

|财务|核对结算依据|查看验收结果、对账明细、导出|只读|
|只读|了解履约状态|查看列表与详情|只读|

## 2.2 核心场景

|   |   |
|---|---|
|场景名称|场景内容|
|门店直采单待确认，供应商逐单接单（高频）|门店提交直采单后，订单进入「待确认」。供应商在**全部订单（D01）**检索到该单，进**订单详情（D02）**看明细、门店下单备注与配送日期，点「确认接单」或「拒绝接单」。确认后状态转「已确认」，系统自动生成唯一待发货单；拒绝必须填原因。|
|按门店配置自动确认（可逆）|供应商在**接单设置（D12）**按门店设置「即时自动确认 / 延迟自动确认 / 人工确认」。总开关只作急停用，关闭后全部门店暂按人工确认，各店配置保留。配置只对生效后新提交的直采单生效，不回溯历史待确认单。|
|按备货日一次备完|供应商打开**备货参考（D03）**，默认看明天，可按起止范围查多日。页面按商品汇总三店需求，预告缺口已逐店扣减，建议备货 = 下单合计 − 已预告缺口之和。列表高度随视口自适应，仅表格内部滚动。|
|核对实发量并确认发货（主链）|**发货管理（E01）**只列系统自动生成的发货单，实发量按下单量（足量）预填并标「待核对」。进**发货单编辑（E02）**逐行核对，填送达时间，校验通过后保存；再到**发货单详情（E04）**点「确认发货」，冻结数量与备注、生成送货单、订单转「已发货」。|
|食安报告自动命中与补充|系统按商品 pid 与发货日期有效期自动关联最新一份报告（操作人「系统自动」）。供应商可在 E02 明细行内按有效期起止、上传时间起止、上传人筛选候选报告，或新增上传并填写有效期。报告内容可点缩略图放大预览。|
|验收结果只读回写，结算按合格量定稿|门店完成验收后，供应端在**验收结果（F01）**看到验收单，进**验收详情（F02）**逐行核对“应收 → 实发 → 实收 → 合格”。结算金额 = Σ（合格量 × 单价），供应商不可改验收结论。|
|退货申请限时处理|门店发起退货，**售后退货（F04）**显示待确认徽标。供应商进**退货处理进度（F05）**看时间轴、退货凭证照片与退货信息，点「处理」选择同意或驳回。同意后该批不计入合格量，结算自然扣减；超时默认同意。|
|按对账日期核对金额|**结算对账（G01）**按对账日期、门店、档口筛选，点「对账明细」进 G02。G02 逐行展示应发量 / 实收量 / 拒收量 / 已通过退货量 / 合格量 / 单价 / 金额 / 扣减，任意一行都能自行验算。|

## 2.3 完整流程

|步骤|页面|系统给了什么|走不通时会怎样|
|---|---|---|---|
|1|全部订单（D01）|订单来自门店直采或询价中标；列表按订单号 / 类型 / 门店 / 状态 / 配送日期检索|无新建入口；上游单据不展示、不筛选、不导出|
|2|订单详情（D02）|按订单号渲染商品行、下单备注、步骤条与流转记录；首次打开登记已读回执|待确认才可确认 / 拒绝；终态只读|
|3|接单设置（D12）|按门店配置直采单确认方式；总开关可急停|配置后新单生效；历史待确认单仍需人工处理|
|4|备货参考（D03）|按备货日聚合商品需求，逐店扣减已预告缺口|起始晚于结束拦截；不实现线路 / 分装|
|5|发货管理（E01）|订单确认 / 中标生成时系统自动生成唯一待发货单，实发量预填足量|未核对保存前不给「确认发货」|
|6|发货单编辑（E02）|逐行核对实发量、本行不发、备注；报告自动关联结果只读展示|未勾本行不发且实发量为 0 / 空 / 非整件数，标红拦截|
|7|发货单详情（E04）|核对保存后出现「确认发货」；待发货态报告列只读|确认后数量、备注、时间锁定；只生成一次送货单|
|8|食安报告库（E11）|报告独立入库，按 pid 与有效期被引用；详情可预览图片 / PDF / 表格|过期 / 未生效 / 作废报告不进候选；历史引用不追改|
|9|验收结果（F01）/ 验收详情（F02）|门店验收结论回写，结算金额按合格量现算|供应商只读；一期无申诉 / 改判|
|10|售后退货（F04）/ 退货进度（F05）|门店退货单可查看凭证并处理；同意即结算扣减|超时默认同意；驳回维持原结算|
|11|结算对账（G01）/ 对账明细（G02）|按对账日期实时计算，按门店 / 档口筛选；逐行展示验算链|无对账单号 / 账期；档口须先选门店|

# 3. 术语与核心口径

## 3.1 术语

|术语|业务定义|
|---|---|
|门店直采订单|门店直接提交的采购订单，待确认时供应商可确认或拒绝|
|询价中标订单|报价中标后系统生成的订单，状态直接为「已确认」，不可拒绝或取消|
|采购档口|采购主体的最小粒度。同店不同档口视为不同订单、发货与对账单元|
|配送日期|门店下单时填写的到货日期；订单中心与导出统一使用该字段名|
|配送时间|发货管理中由「配送日期 + 送达时间（时分）」拼成的展示字段；筛选按配送日期|
|送达时间|发货单上选填的实际到店时刻（时分），不写订单、不参与金额|
|发货日期|系统按订单配送日期建单时带入，供应端全程只读，是食安报告有效期判定基准|
|订单承诺|订单确认后形成的履约义务；一单一发，不分批、不拆单、不追加|
|发货单|系统在订单确认 / 中标生成时自动创建的唯一待发货单据|
|预填量|发货单商品行按订单下单量（足量）预填的估算值，不是实发量|
|实发量|供应商按实际出库核对后的数量；确认发货时冻结|
|本行不发|供应商对整行不供货的标记；勾中后实发量锁定，不计入发货金额|
|送货单|确认发货时按冻结内容生成的随货同行联，单号沿用发货单号|
|食安报告|含有效期、上传人、上传时间与图片 / 文件集合的合规凭证，独立入报告库|
|报告引用|发货行只存 reportId 与 pid / sid 关系，不复制报告内容|
|自动关联|系统按 pid 反查历史报告，取有效期覆盖发货日期且上传时间最新的一份写入引用|
|验收单|门店验收结论回写后生成的只读单据，是结算唯一依据|
|合格量|实收量 − 拒收量；在结算中还需扣除已通过的退货量|
|拒收|门店现场判定不收的数量，直接计入差异，不进结算金额|
|退货申请|门店事后发起的退货单，供应商限时处理；通过后自然扣减|
|对账日期|结算对账列表的唯一时间字段；按订单数据实时计算，无对账单号与账期|
|应结金额|对账金额 − 扣减；扣减来自拒收与已通过退货|
|流转记录|按真实状态变更时间记录动作、节点与操作人；系统动作不标操作人|

## 3.2 模块位置

本文档覆盖四个相邻的履约模块，在页面上表现为侧栏四个二级分组：

|   |   |
|---|---|
|模块名|模块内容|
|订单中心|导航下 3 个子项：全部订单（D01）/ 备货参考（D03）/ 接单设置（D12）。订单详情（D02）是详情页，不出现在导航里，只能从订单列表或其它单据跳入。|
|发货与分拣|导航下 2 个子项：发货管理（E01）/ 食安报告库（E11）。发货单编辑（E02）、发货单详情（E04）是操作 / 详情页，不出现在导航里。|
|验收与售后|导航下 2 个子项：验收结果（F01）/ 售后退货（F04）。验收详情（F02）、退货处理进度（F05）是详情页，不出现在导航里。|
|结算对账|导航下核心子项：结算对账（G01）。对账明细（G02）是详情页，不出现在导航里；结算单（G03）与收款记录（G04）不在本期范围。|

> 四个模块之间只有一条主链：**订单 → 发货 → 验收 → 对账**。退货是验收后的逆向分支，食安报告是发货环节的合规旁挂，不进入金额计算。

# 4. 核心业务对象

## 4.1 业务对象

|对象|谁产生|它代表什么|供应商能改吗|
|---|---|---|---|
|采购订单（PO）|门店直采提交 / 询价中标生成|一条采购承诺，含门店 / 档口 / 行 / 金额 / 状态|待确认直采单可确认或拒绝；不可改量、议价、加品|
|订单行|订单创建时由门店需求生成|到「商品 · 规格 · 单位」粒度，含下单量与单价|不能改|
|接单配置|供应商在 D12 保存|按门店决定直采单自动 / 延迟 / 人工确认|能，按门店改|
|备货汇总行|按备货日范围从订单行派生|商品维度的需求量、预告缺口与建议备货|不能，只能查询 / 导出|
|发货单|订单确认 / 中标生成时系统自动创建|一单一发的履约单据|待发货可核对保存；确认后只读|
|发货行|发货单创建时从订单行派生|实发量、本行不发、备注、报告引用|确认前可改，确认后冻结|
|送货单|确认发货时生成|随货同行联，记录应发 / 实发与差异备注|只读，可打印|
|食安报告|在 E02 / E04 明细行内上传|有效期覆盖发货日期的合规凭证|可新增、作废；引用后内容不可变|
|报告引用|系统自动写入或人工补充|发货行 → 报告的关系，含 scene 与 pid / sid|待发货可解绑 / 补充；已发货只追加|
|验收单|门店验收结论回写后生成|结算唯一依据|供应商只读|
|验收行|从关联发货行派生|应收 / 实发 / 实收 / 拒收 / 合格量 / 单价|供应商只读|
|退货申请|门店发起|事后退货请求，含凭证、原因、数量与金额|供应商可同意 / 驳回，不能改申请内容|
|对账记录|按对账日期从订单 / 验收 / 退货实时派生|门店 · 档口维度的应结金额|不能改，只能查看 / 导出|

## 4.2 派生规则

|   |   |
|---|---|
|项|规则|
|**订单金额**|Σ（下单量 × 下单单价）。仅计重单位（kg / 斤）允许 1 位小数，其余包装单位为正整数。|
|**验收总金额**|Σ（验收合格量 × 单价）。无验收单时列表显示 `-`。|
|**发货金额**|Σ（实发量 × 单价），本行不发行计 0。未核对保存前标「预估」。|
|**合格量**|验收合格量 = 实收量 − 拒收量；结算合格量（不含退货）= 实收量 − 拒收量 − 已通过的退货量。|
|**结算金额**|Σ（结算合格量 × 下单单价）。退货只取 F04 / A06 中状态为「已同意」的申请，待确认 / 已驳回不进账。|
|**对账金额**|按门店 · 档口 · 对账日期聚合的结算金额；扣减 = 拒收金额 + 已通过退货金额；应结金额 = 对账金额 − 扣减。|
|**建议备货**|商品在备货日范围内的下单合计 − 该商品各门店已预告缺口之和。|
|**报告有效期判定**|按发货单的发货日期（非业务今天）判断报告是否命中；有效期含首尾。|
|**自动关联**|按 pid 反查历史报告，筛有效期覆盖发货日期者，取上传时间最新一份；每行最多一份。|
|**徽标 / 计数**|所有状态标签、页脚数字、徽标与列表行数一律从实际数据现算，不允许写死。|

# 5. 业务规则

以下规则跨页面生效。若某个页面的局部做法与本章冲突，以本章为准。

|编号|主题|核心规则|说明 / 原因|
|---|---|---|---|
|BR-01|订单只有两个来源|订单由门店直采提交或询价中标生成；供应端无新建订单入口，不提供改量、议价、加品。|订单是采购承诺，供应商侧改写会让价格、验收与对账失去同一基准。|
|BR-02|确认即承诺|直采单确认后不可改、不可取消；中标单生成即「已确认」，不可拒绝。供不上走缺货预告与发货差异备注。|确认后再改会让已生成的发货单与门店预期脱节。|
|BR-03|采购主体到档口|同店不同档口的订单、发货与对账都是独立单元，列表 / 详情 / 导出均带档口。|档口的规格、送货频次与结算口径不同，合并会错账。|
|BR-04|一单一发|一张订单对应唯一一张系统自动生成的发货单，只确认发货一次；不分批、不拆单、不追加。短装按实发结算，补发另开订单。|二次发货会破坏送货单与验收单一一对应关系。|
|BR-05|自动建单路径|直采单确认接单、中标单中标生成时，系统自动创建待发货单；询价中标路径无需人工确认。|建单是状态推进的副作用，不依赖人工补建。|
|BR-06|订单状态推进|仅「确认发货」把订单推进为「已发货」；门店首次提交验收数据进「验收中」，结论回写进「已完成」。不单列订单「已验收」。|状态表达履约节点，不重复表达验收单对象。|
|BR-07|真实时间口径|流转记录取真实状态变更时间：创建 / 确认 / 确认发货 / 首次验收 / 验收完成 / 撤回 / 关闭；无「现在」占位节点。|流转时间是争议追溯依据，不能随渲染时间漂移。|
|BR-08|操作人标注|流转记录时间行旁标操作人；系统动作（系统自动生成、系统校验、平台开票等）不标。|人工动作可追责，系统动作标注反而干扰阅读。|
|BR-09|已读回执|首次打开待确认 / 已拒绝 / 已关闭订单登记查看时刻与查看人；已有回执不覆盖。回执不改状态。|“看过”是独立事实，不改变承诺状态。|
|BR-10|不提供批量确认|确认逐单在 D02 完成，不提供列表批量确认。|确认即承诺，需要逐单看明细与备注。|
|BR-11|接单配置按门店|自动确认按订单所属门店取规则，一店一条；总开关仅作急停用，关闭后各店配置保留。|A 店自动、B 店人工互不干扰。|
|BR-12|配置不回溯|接单配置只对生效后新提交的直采单生效；历史待确认单仍需人工处理。改回人工或关闭总开关时，该店未执行的延迟任务取消。|避免配置变更推翻已挂起的处理动作。|
|BR-13|确认来源留痕|自动确认与人工确认在履约、结算、打印上完全一致，仅流转记录标注来源。|履约结果不应因确认方式不同而分叉。|
|BR-14|配送日期与送达时间|门店下单只填配送日期；发货日期由配送日期带入且只读；送达时间为发货单选填的时分，不写订单、不参与金额与筛选。|日期是业务承诺，时刻是实际执行记录。|
|BR-15|预填不是实发|发货行实发量按下单量（足量）预填，列表标「待核对」、金额标「预估」；保存前不给确认发货。|预填只为减少录入，不能替代实际出库核对。|
|BR-16|整件数校验|未勾「本行不发」且实发量为空 / 0 / 非整件数不允许保存；计重单位允许 1 位小数。问题行标红并列出行号。|包装单位下单的货不能发 3.5 件。|
|BR-17|保存与确认分离|「保存」只写回待发货单与保存时间，不改状态、不锁定、不生成送货单；「确认发货」才冻结数据、生成送货单、推进订单。|核对阶段必须可反复修改，避免误填直接锁单。|
|BR-18|本行不发|整行不供勾「本行不发」，实发量锁定、金额计 0；「本行不发 / 实发 0」不挂食安报告、不可补传。|不发就不产生履约与合规材料。|
|BR-19|无新增商品行|发货仅在订单承诺范围内落数，不留空白行、不新增商品。|多出的货无预算、无验收标准、无法结算。|
|BR-20|确认发货三件事|冻结实发量与备注、生成送货单、订单转「已发货」；不创建验收单。|已发货 · 待验收是正常中间态。|
|BR-21|报告是资产，发货单存引用|报告在 E02 / E04 明细行内上传一次进报告库，可被多单多行引用；E11 只做管理维护，无新增入口。|报告内容不复制进发货快照，历史引用不追改。|
|BR-22|pid 匹配|自动关联按商品 pid / sid 而非品名 + 规格文本；商品改名或改包规不断链。|文本会变，平台主数据身份不会变。|
|BR-23|自动关联口径|按发货日期判断有效期，取命中报告中上传时间最新一份；scene=自动、操作人「系统自动」。每行最多一份，已有引用不替换。|自动关联只补“应当有”，不覆盖人工判断。|
|BR-24|报告候选过滤|已过期 / 未生效 / 已作废报告不进候选；关联弹窗按有效期起止、上传时间起止、上传人筛选，起止留空不限。|避免把不可用报告挂到发货单上。|
|BR-25|报告只影响合规|报告不参与合格量、验收结论、结算金额；未关联不提示、不阻塞确认发货、不产生待办。|合规材料与金额链路隔离。|
|BR-26|验收即结算依据|验收结论由门店录入并回写，供应商只读；一期无申诉 / 改判入口。结算金额 = Σ（合格量 × 单价）。|结论回写即定稿，避免双口径。|
|BR-27|合格量口径|合格量 = 实收 − 拒收；多发不多收，少发必少收。下单量、发货量均不直接进结算。|结算只认门店实际收下的数量。|
|BR-28|售后范围|F04 仅处理门店发起的退货申请；验收异议申诉 / 改判一期不做。状态仅待确认 / 已同意 / 已拒绝。|两类业务主体与处理动作不同，不混在一个列表里。|
|BR-29|退货时限|门店发起后 72 小时内处理，超时默认同意。|避免退货悬而未决影响对账。|
|BR-30|退货扣减|审核通过即不计入验收合格量，结算时自然扣减，无独立退款动作；驳回维持原结算。|退货通过改的是数量口径，不是另开一笔钱。|
|BR-31|对账实时计算|对账记录按订单数据实时计算；列表与详情不展示对账单号与账期，只展示对账日期。|对账是推导过程，不是提前生成的单据。|
|BR-32|档口前置门店|对账筛选中档口下拉默认禁用并提示「请先选择门店」；选门店后才列出该店档口。|各门店档口名可能不一致，必须先限定门店。|
|BR-33|逐行可验算|对账明细逐行展示应发 / 实收 / 拒收 / 已通过退货 / 合格 / 单价 / 金额 / 扣减，四段排开。|金额可自己算出来，争议才有依据。|
|BR-34|通用分页|列表分页统一使用 `pgSlice` / `pgFoot`：按屏保存页码与每页条数，切页只改状态再重渲染。E11 默认 5 条/页，可选 5 / 10 / 20。|短列表不产生分页噪音，长列表不重复造组件。|
|BR-35|返回按来源|顶部返回按钮按进入来源显示文案与去向：D01 返回列表、E01 返回列表、D02 返回详情、F05 进入 D02 返回退货详情。|返回错页会打断作业路径，尤其在跨模块跳转时。|
|BR-36|规则说明统一入口|页面规则统一走页头「规则说明」弹层；E11 底部独立「报告库规则」卡片已移除。|规则只维护一处，避免页面与弹层口径分叉。|

# 6. 状态及流转

## 6.1 状态定义

**订单状态**

|状态|含义|这时能做什么|算不算待办|
|---|---|---|---|
|待确认|门店直采单已提交，供应商未处理|确认接单 / 拒绝接单|是|
|已确认|直采单已确认或中标单已生成|缺货预告、查看发货单|否|
|已发货|供应商已确认发货|只读查看发货单与送货单|否|
|验收中|门店首次提交验收数据|只读|否|
|已完成|门店验收结论已回写|只读，查看验收结论|否|
|已拒绝|供应商拒绝直采单|只读|否|
|已关闭|门店撤回，或过配送日期未发货自动关闭|只读|否|

**发货单状态**

|状态|含义|这时能做什么|
|---|---|---|
|待发货（待核对）|系统自动建单，实发量为足量预填，未保存核对|修改实发量、本行不发、备注、发货人 / 电话、送达时间；报告只读 / 可补充|
|待发货（已核对）|已按实际出库保存，但尚未确认发货|查看、修改、确认发货|
|已发货|确认发货完成，数据冻结，已生成送货单|查看、打印、已发货后补传报告|
|验收中|门店已提交验收数据|只读|
|已完成|门店验收结论回写|只读，可看验收结果|
|已关闭|订单关闭时同步作废|只读|

**食安报告状态**

|状态|含义|能否用于新关联|
|---|---|---|
|有效|业务今天落在有效期内且未作废|是|
|未生效|生效日晚于业务今天|否|
|已过期|失效日早于业务今天|否|
|已作废|逻辑删除，历史引用保留|否|

**退货申请状态**

|状态|含义|供应商动作|
|---|---|---|
|待确认|门店已发起，尚未处理|同意 / 驳回|
|已同意|审核通过，已产生结算扣减|只读查看|
|已拒绝|审核驳回，维持原结算|只读查看|

## 6.3 禁止动作

|想做的动作|系统的反应|
|---|---|
|新建采购订单|不提供入口，订单只来自门店直采 / 询价中标|
|改订单数量、单价、加品、议价|不提供入口；门店需调整时撤回后重新提交|
|批量确认订单|不提供；逐单在 D02 处理|
|未保存核对直接确认发货|不给「确认发货」按钮，提示先核对实发量|
|确认发货后改数量 / 备注 / 时间|字段只读，无线上更正 / 重开入口|
|在原发货单追加批次或二次确认|不提供；短装按实发结算，补发另开订单|
|已发货后替换 / 解绑报告|不提供，只允许追加补传|
|作废未完成验收的订单|不提供；过配送日期未发货由系统自动关闭|
|修改验收结论 / 合格量|不提供，验收数据由门店回写且只读|
|对已同意 / 已拒绝退货再次处理|操作列只显示「已处理」，不提供处理入口|
|手工生成对账单号或账期|不提供；对账按日期实时计算|

# 7. 功能需求

## 7.1 D01 全部订单

**FR-D01-1 页面目标与入口**

全部订单是订单中心的唯一列表视图，负责检索与定位。入口：侧栏「订单中心 → 全部订单」、C07 中标结果「查看正式订单」、其它单据的订单号链接。

**FR-D01-2 页面构成**

页头 + 筛选区 + 列表 + 底部分页。页头副标题固定说明订单来源；右上按钮为「导出」「接单设置」。

**FR-D01-3 筛选区**

|字段|规则|
|---|---|
|订单类型|全部类型 / 门店直采 / 询价中标|
|订单状态|全部状态 + 订单状态枚举|
|采购门店|全部门店 + 门店列表|
|配送日期|起止日期区间，按日期筛选|
|订单号|模糊匹配|
|操作|查询 / 重置|

**FR-D01-4 列表字段（11 列）**

订单号 / 订单类型 / 采购门店 / 采购档口 / 配送日期 / 行数 / 预估金额 / 验收总金额 / 状态 / 售后情况 / 操作。

- 预估金额按下单量 × 单价现算；验收总金额取关联验收单结算金额，无验收单显示 `-`。
- 售后情况显示该验收单下「已同意」退货单条数，0 条走次要色。
- 申请撤回的订单在状态列追加「申请撤回」标签。
- 操作列按当前状态给「详情 / 确认 / 拒绝 / 查看发货单」入口，列表不承担状态变更弹窗。

**FR-D01-5 导出**

沿用当前筛选条件，单次上限 5,000 行，超限按配送日拆分。导出字段包含配送日期、下单金额、验收金额与缺货预告行数；导出为只读操作，不改状态、不触发通知，记录操作人与时间。

**FR-D01-6 底部统计与分页**

底部显示「共 N 条记录 · 待处理 M 条」，M = 待确认 + 申请撤回。分页提供每页条数、上一页 / 下一页与页码；页码只影响展示，不改变统计口径。

## 7.2 D02 订单详情

**FR-D02-1 页面目标与入口**

按订单号渲染单张订单，是待确认订单唯一可确认 / 拒绝的页面。入口：D01「详情」、E01 关联订单号、F05「关联采购订单」、其它单据跳转。

**FR-D02-2 页头与返回**

- H1 显示订单号；副标题显示类型 / 来源渠道 / 确认方式 / 门店 · 档口 / 行数 / 金额 / 配送日期。
- 右上角返回按钮按来源显示：D01 →「返回列表」；E01 →「返回列表」；E04 →「返回详情」；**F05 →「返回详情」并回到原退货进度**。
- 状态标签按当前订单状态显示；待确认订单显示「确认接单 / 拒绝接单」，已确认显示「缺货预告 / 查看发货单」。

**FR-D02-3 步骤条与横幅**

按订单状态显示「门店提交 / 中标生成 → 已确认 → 已发货 → 验收中 → 已完成」。待确认状态展示履约提示横幅；终态步骤条全部标完成，不显示「当前」节点。

**FR-D02-4 订单信息**

展示订单号、订单类型、来源渠道、确认方式、采购门店 / 档口、所属商户、确认时间、下单时间、已读回执、配送日期、预占金额、结算口径。确认方式仅显示「待供应商确认 / 中标即确认 / 人工确认」，不重复解释判断依据。

**FR-D02-5 订单明细表（12 列）**

序号 / 商品 · 规格 / 单位 / 下单量 / 实发量 / 验收量 / 单价 / 订单金额 / 验收总金额 / 预管 / 下单备注 / 发货状态。

- 明细来自 `ordLines()`，与 D03 / E02 / E04 / K05 同源。
- 「下单备注」展示门店原文，供应端只读，未填显示 `-`，不写进发货单快照。
- 未发货时预管列可显示缺货预告信息；发货状态按订单与发货单关系现算。

**FR-D02-6 缺货预告与发货单入口**

未发货前可点「缺货预告」，按订单行提交缺口原因；确认发货后入口关闭。已确认可「查看发货单」进入 E04；已发货及之后只读查看。

**FR-D02-7 流转记录**

按真实时间倒序列出节点、动作、状态与时间，时间行旁标操作人；系统节点不标操作人。已完成订单必须依次出现「确认发货 → 进入验收中 → 进入已完成」三段。

## 7.3 D03 备货参考

**FR-D03-1 页面目标与入口**

按备货日范围提供商品维度的备货汇总，不对应具体订单。入口：侧栏「订单中心 → 备货参考」。

**FR-D03-2 页头与查询**

页头右侧为备货日起止两个日期控件，默认两端均为演示口径的明天；起始晚于结束时拦截并提示。查询写回范围并重渲染，「导出备货单」为只读操作并记录操作人与时间。

**FR-D03-3 单一视角：按商品汇总**

表格只有「按商品汇总」一个视角，不另起门店统计表。门店列仅显示门店名，值为该店在备货日范围内所有订单的采购合计，不展示订单号。

**FR-D03-4 表格字段**

商品 / 规格 / 单位 / 下单合计 / 已预告缺口 / 建议备货 / 各门店列。

- 商品列展示品名 + 规格两行；规格按品名从订单行主数据取，与 D02 / E02 / E04 / K05 同源。
- 已预告缺口 = 各门店缺口之和；建议备货 = 下单合计 − 已预告缺口。
- 门店格子上行显示下单量，下行显示「预告 −N / 缺口 0 / 未订」；悬停橙色缺口查看原因、食堂回音与预告时间。

**FR-D03-5 冻结列与视口自适应**

商品 / 单位 / 下单合计 / 已预告缺口 / 建议备货五列冻结于左侧，表头冻结；门店列在右侧滚动区。页面高度按视口自适应，只出现表格内部滚动，不出现整页全局滚动条；冻结列右缘带分隔阴影。

**FR-D03-6 一期边界**

不实现线路、配送时段、装车顺序与按门店分装；门店列只标注缺口归属，不是分装作业单。

## 7.4 D12 接单设置

**FR-D12-1 页面目标与入口**

配置门店直采订单的确认方式。入口：侧栏「订单中心 → 接单设置」、D01 页头「接单设置」。

**FR-D12-2 自动确认总开关**

总开关开启后，门店提交直采单按各店配置自动确认；关闭后全部门店暂按人工确认，各店配置保留，重新开启即恢复。页头与列表上方同步显示当前生效状态。

**FR-D12-3 按门店配置表（5 列）**

门店 / 接单方式 / 延迟分钟 / 自动确认后通知门店 / 当前生效。

- 门店列第一行显示门店名，第二行显示商户名称，不显示商户 / 门店编码。
- 接单方式：即时自动确认 / 延迟自动确认 / 人工确认。
- 延迟分钟与通知只在自动确认方式下可用；人工确认时禁用。
- 「当前生效」按总开关与门店配置实时派生，不另存一个状态字段。

**FR-D12-4 批量套用**

可将一种接单方式应用到全部门店；只填入本页表单，点「保存设置」后才生效。个别门店随后仍可单独改回。

**FR-D12-5 规则边界**

页面固定展示：按门店取规则、不创建订单、不回溯历史待确认单、并发只成功一次、改回人工即取消未执行延迟任务、确认即承诺、确认即自动建单。

## 7.5 E01 发货管理

**FR-E01-1 页面目标与入口**

发货单的索引视图，只列系统自动生成的发货单。入口：侧栏「发货与分拣 → 发货管理」、A04 待办。

**FR-E01-2 页面构成**

页头 + 筛选区 + 列表 + 底部分页。页头说明系统建单与一单一发；右上「导出」沿用当前筛选。

**FR-E01-3 筛选区**

全部状态 / 全部门店 / 配送时间起止 / 发货单号或订单号模糊匹配 / 查询 / 重置。筛选按配送日期，送达时刻只展示不参与筛选。

**FR-E01-4 列表字段（10 列）**

发货单号 / 关联订单 / 门店 / 采购档口 / 配送时间 / 行数 / 实发金额 / 变动行 / 状态 / 操作。

- 实发金额在待核对时显示「预估 ¥X」，核对保存后显示正式金额。
- 未核对保存的待发货单状态列追加「待核对」标签。
- 变动行 = 实发量与下单量不一致的行数。
- 待发货行操作为「修改 + 查看」，已发货及之后只有「查看」。

**FR-E01-5 确认发货入口**

E01 列表不直接弹确认框；点「查看」进 E04，核对完成后在 E04 点「确认发货」。列表对已核对保存的单提供直达查看入口。

## 7.6 E02 发货单编辑

**FR-E02-1 页面目标与入口**

待发货单唯一可编辑页。入口：E01 待发货「修改」、E04「修改发货信息」、E02「下一步：查看发货单」前的保存路径。

**FR-E02-2 页头字段**

展示发货单号、关联订单、门店 · 档口、配送日期（发货日期）与行数。发货日期只读，提示由订单配送日期带入。

**FR-E02-3 可编辑字段**

发货人（默认当前账号姓名）、联系电话（默认账号绑定手机号）、送达时间（时分，选填）、整单备注。送达时间只补当天实际到店时刻，不改日期、不参与金额、不作为筛选维度。

**FR-E02-4 发货明细表（10 列）**

序号 / 品名 · 规格 / 单位 / 下单量 / 预估备货量 / 实发量 / 单价 / 订单金额 / 本行不发 / 备注 / 食安报告。

- 单价取订单行单价；订单金额 = 下单量 × 单价，与 D02 同口径，不按实发量重算。
- 实发量可反复修改；本行不发勾中后输入框锁定。
- 食安报告列显示自动关联 chip、解绑入口与「＋ 选择 / 上传报告」。

**FR-E02-5 行级校验**

点「保存 / 保存并返回 / 保存并查看发货单」时逐行检查：未勾本行不发且实发量为空 / 0 / 非整件数则顶部列出问题行号，输入框红框、整行浅红底，提示「请填 >0 的整件数」。用户修正后红框立即消失。

**FR-E02-6 食安报告关联弹层**

弹层上半区只读展示系统自动关联结果；下半区为「筛选报告库」：

|筛选项|控件|口径|
|---|---|---|
|有效期起止|两个日期输入|报告有效期与查询区间有交集即命中，起 / 止留空不限|
|上传时间起止|两个日期输入|上传当天落在区间内，起 / 止留空不限|
|上传人|文本输入|模糊匹配|
|仅本商品历史|复选框|只列该 pid 历史引用过的报告|

候选报告仍须满足：未作废、有效期覆盖本单发货日期、未在本行关联。勾选后点「确认关联」才写入；新增报告必须填有效期并关联本行。

**FR-E02-7 保存语义**

保存成功写回待发货单与保存时间，状态不变、不锁定、不推进订单、不生成送货单。报告关联 / 解绑后只刷新该列与汇总栏，不冲掉未保存输入。

## 7.7 E04 发货单详情

**FR-E04-1 页面目标与入口**

发货单的唯一单据页，按状态在“可核对”和“只读快照”之间切换。入口：E01「查看」、D02「查看发货单」、E02「保存并查看发货单」。

**FR-E04-2 页头与返回**

- 从 E01 进入显示「返回列表」，从 D02 进入显示「返回详情」。
- 待发货显示「修改发货信息」；已核对保存后才出现「确认发货」；已发货后显示送货单入口与补传入口。
- 待发货态食安报告列只读，不再显示「发货前在 E02 关联」或 E02 跳转提示。

**FR-E04-3 页面构成**

顶部信息卡 + 发货明细全宽表 + 汇总栏 + 流转记录。发货明细与 E02 同一形态，含单价与订单金额列，最右列为食安报告。

**FR-E04-4 待发货态**

显示当前可改内容但本页不提供编辑控件；食安报告列只读展示自动关联结果，操作提示仅显示「待发货只读」。不提供「确认发货」直到完成核对保存。

**FR-E04-5 已发货态**

数量、备注、时间、单价与金额全部冻结；食安报告列显示「＋ 补传报告」，点击进关联弹层，只追加不替换、不显示解绑。补传走独立写入口，不改数量 / 金额 / 时间 / 状态 / 送货单，只在流转记录增「补传食安报告 · N 份」。

**FR-E04-6 送货单**

未发货时打印按钮提示「未生成」。确认发货时按冻结内容生成随货同行联，单号沿用发货单号；E04 与 K05 打印预览均可打开。

**FR-E04-7 验收中环节**

门店首次提交验收数据进入「验收中」，结论回写进入「已完成」。判断依据是发货单状态与时间字段，不依赖验收单对象是否存在；流转记录必须包含四段，无验收明细的历史单也展示完整流转。

## 7.8 E11 食安报告库

**FR-E11-1 页面目标与入口**

报告库的管理维护视图：详情、作废、按报告反查引用。报告只在 E02 / E04 明细行内创建，E11 无新增 / 上传入口。入口：侧栏「发货与分拣 → 食安报告库」。

**FR-E11-2 筛选区**

报告 ID 模糊 / 状态 / 有效期起止 / 上传日期起止 / 查询 / 重置。有效期按与区间有交集判定，上传日期按上传当天落在区间内，起 / 止留空即不限；筛选只影响本页可见行。

**FR-E11-3 列表字段（7 列）**

报告名称 / ID / 有效期 / 状态 / 上传信息 / 上传内容 / 被引用 / 操作。操作为「详情」「作废」；已作废报告保留详情入口。

**FR-E11-4 分页**

列表底部使用通用分页组件，默认 5 条/页，可选 5 / 10 / 20。页码与每页条数按屏保存，翻页只重渲染列表。底部独立「报告库规则」卡片已移除，规则统一走页头「规则说明」。

**FR-E11-5 报告详情弹层**

展示报告 ID、上传时间、上传人、状态、有效期与文件缩略图。图片 / PDF / XLSX 均可点击放大预览；下方列出引用记录，按发货单 / 门店 / 商品 pid / 发货时间逐条展示。

**FR-E11-6 作废**

作废采用逻辑删除：历史发货单已关联的记录仍可查，但不再出现在新关联候选。作废需二次确认，记录作废时间、操作人与原因；名称序号不回收。

## 7.9 F01 验收结果

**FR-F01-1 页面目标与入口**

验收结果的只读台账。入口：侧栏「验收与售后 → 验收结果」。

**FR-F01-2 筛选区**

全部门店 / 验收时间起止 / 验收单号或发货单号 / 查询 / 重置。页面固定提示“数据由食堂侧回写，供应商只读”。

**FR-F01-3 列表字段（8 列）**

验收单号 / 发货单 / 门店 / 采购档口 / 验收时间 / 差异行 / 结算金额 / 操作。

- 验收单条数与「已完成」订单一一对应；`shipAudit()` 双向校验。
- 结算金额与差异行从验收明细现算，不写死汇总数字。
- 点发货单号进 E04，点「查看」进 F02。

**FR-F01-4 底部分页**

全量展示验收单，底部分页提供每页条数与页码；页头计数由 ACCEPTANCES 现算。

## 7.10 F02 验收详情

**FR-F02-1 页面目标与入口**

单张验收单的逐行核对页。入口：F01「查看」、其它单据按验收单号跳入。

**FR-F02-2 信息卡**

展示验收单号、关联发货单、门店 · 档口、验收时间、验收结论、差异行数与结算金额。

**FR-F02-3 明细表**

序号 / 商品 · 规格 / 单位 / 应收量 / 实发量 / 实收量 / 拒收量 / 合格量 / 单价 / 金额 / 说明。

- 明细行数、品名、数量与单价全部跟随关联发货单商品行。
- 仅核对数量与包规；不按商品等级做品质分级。
- 合格量 = 实收 − 拒收；结算金额 = Σ（合格量 × 单价）。
- 供应商不可改任何验收字段。

**FR-F02-4 返回规则**

从 F01 列表进入显示「返回列表」；从 F05 退货单进入显示「返回退货单」；从 E04 进入显示「返回发货单」。

## 7.11 F04 售后退货处理

**FR-F04-1 页面目标与入口**

门店退货申请的处理台账。入口：侧栏「验收与售后 → 售后退货」。

**FR-F04-2 KPI 与页头**

页头显示「待确认 N 单」tag，右上「导出」沿用当前筛选。KPI 包含本月退货单数、待确认数、待确认扣减金额与平均处理时长，全部现算。

**FR-F04-3 筛选区**

状态 / 门店 / 申请时间起止 / 处理时间起止 / 退货单号 · 关联采购订单号 · 商品名模糊匹配 / 查询。

**FR-F04-4 列表字段（12 列）**

退货单号 / 关联采购订单号 / 门店 / 采购档口 / 退货商品 / 数量 / 金额 / 退货原因 / 申请时间 / 处理时间 / 状态 / 操作。

- 关联采购订单号可点击进 D02；从 F04 进入时 D02 返回按钮文案按来源处理。
- 待确认行操作为「查看 + 处理」，已处理行只显示「查看」。

**FR-F04-5 处理弹层**

处理结论为「同意（结算扣减）」或「驳回」；驳回时处理说明必填。提交后原地刷新，KPI、徽标与流转记录同步更新。

**FR-F04-6 超时默认同意**

门店发起后 72 小时未处理，系统自动置为「已同意」，流转记录标注超时来源。

## 7.12 F05 退货处理进度

**FR-F05-1 页面目标与入口**

单张退货申请的进度页。入口：F04「查看」、A06 待办。

**FR-F05-2 页头与返回**

H1 显示退货单号；副标题显示商品 / 原因 / 门店 · 档口 / 金额 / 申请时间。右上为「返回列表」「关联采购订单」「处理（待确认时）」。

从 F05 点「关联采购订单」进入 D02 时，D02 顶部显示「返回详情」，点击后回到**同一张 F05 退货单**。

**FR-F05-3 时间轴**

节点固定为「门店发起 → 系统校验 → 供应商审核」，通过后追加结算扣减说明，驳回则维持原结算。时间行旁标操作人；系统校验节点不标。

**FR-F05-4 退货凭证**

展示门店收货照片缩略图，点击放大查看；放大图注明退货单号、门店、档口、商品、拍摄时间与红框问题标注。原型无真实图片文件，按退货单生成模拟实拍图。

**FR-F05-5 退货信息与历史**

展示商品、数量、原因、扣减金额与状态；下方列出历史同类退货。无申诉 / 证据对照 / 改判金额等验收异议元素，也无独立「取回 / 退款」动作。

## 7.13 G01 结算对账

**FR-G01-1 页面目标与入口**

按对账日期浏览门店 · 档口维度的应结金额。入口：侧栏「结算对账 → 结算对账」。

**FR-G01-2 KPI**

展示「本月对账金额」与「扣减合计」，两者从对账记录现算。扣减合计注明占对账金额比例与“全部可追溯”。

**FR-G01-3 筛选区**

月份 / 门店 / 档口。档口下拉默认禁用并显示「请先选择门店」；选具体门店后只列该店档口。切门店或回「全部门店」时，档口回到禁用态。

**FR-G01-4 列表字段（8 列）**

对账日期 / 门店 / 档口 / 订单数 / 对账金额 / 扣减 / 应结金额 / 操作。

- 不展示对账单号与账期；对账日期为唯一时间字段。
- 未选档口时档口列显示「所有档口」；选择具体档口后显示该档口名称。
- 数据由订单实时计算，筛选只影响展示，不改数据。
- 点「对账明细」进 G02，并把门店 / 档口 / 对账日期带入详情页。

## 7.14 G02 对账明细

**FR-G02-1 页面目标与入口**

单条对账记录的逐行验算页。入口：G01「对账明细」。

**FR-G02-2 页头**

显示「门店 · 档口 X · 对账日期 YYYY-MM-DD · N 张订单 · 汇总按货品展开 · 合格量已扣除已通过的退货」。档口沿用 G01 当前筛选值，未选显示「所有档口」。

**FR-G02-3 KPI（4 格）**

应发合计 / 实收合计 / 合格合计（不含退货） / 应结金额。每格副标题给出订单数、短装、拒收、已通过退货与扣减金额。

**FR-G02-4 明细表（11 列）**

商品 / 规格 / 单位 / 应发量 / 实收量 / 拒收量 / 已通过退货量 / 合格量 / 单价 / 金额 / 扣减。

- 规格与单位按品名从订单行主数据取，缺主数据时兜底 `—`。
- 合格量（不含退货）= 实收量 − 拒收量 − 已通过退货量。
- 金额 = 合格量 × 下单单价；扣减 = 拒收金额 + 已通过退货金额。
- 四段数量逐列排开，任何一行都能自行验算。

**FR-G02-5 交互**

「仅显示有扣减的行」复选框只影响展示；「返回列表」回 G01；「导出」输出当前明细。

# 8. 跨模块协作

|关联模块|交接内容|本模块的责任|交接不上时会怎样|
|---|---|---|---|
|询价报价（C06 / C07）|中标行、成交价、配送日期与订单号|中标即生成订单与待发货单，不再要求供应商确认|订单缺失则无法发货与对账|
|门店订单系统|订单创建、撤回、配送日期变更|只读取订单与门店原文备注，不改上游单据|上游改配送日期后发货日期不自动变，需门店重新发起|
|接单设置（D12）|按门店确认方式|按订单所属门店取规则，总开关急停|配置错店会导致不该自动确认的单被确认|
|备货参考（D03）|缺货预告缺口|按订单 · 商品聚合，扣减建议备货|缺口不进备货会导致备货虚高|
|发货管理（E01 / E02 / E04）|实发量、本行不发、备注、送达时间|确认发货时冻结并生成送货单|未冻结则验收与对账无稳定依据|
|食安报告库（E11）|报告有效期、引用关系|按 pid 与发货日期自动关联；报告状态变化不追改历史|报告过期 / 作废后新单不可再用，历史仍可查|
|验收结果（F01 / F02）|合格量、拒收量、结算金额|只读回写，按发货行派生明细|无验收单则订单停在「已发货 · 待验收」|
|售后退货（F04 / F05）|已同意退货的数量与金额|通过后从合格量中扣除，无独立退款|待确认 / 已驳回不进账|
|结算对账（G01 / G02）|对账日期、门店 · 档口、逐行验算链|实时计算，不提前生成单据|缺行或缺口径会让金额不可解释|
|送货单 / 打印（K05）|冻结快照与送货单号|确认发货后生成，单号沿用发货单|打印不推进状态，状态只认验收回写|
|操作日志|确认、拒绝、保存、确认发货、补传、作废、退货处理|主动上报，系统动作标注来源|日志失败不阻断业务，事后补录|

# 9. 异常与边界场景

|编号|场景|处理口径|
|---|---|---|
|EC-01|门店直采单待确认时申请撤回|订单状态追加「申请撤回」标签，D01 待处理数 +1；确认 / 拒绝入口仍按当前状态开放|
|EC-02|订单过配送日期仍未发货|系统自动置「已关闭」，对应待发货单同步作废，不留孤儿单，不进备货 / 发货 / 对账|
|EC-03|同一门店多个档口同时下单|按档口生成独立订单、发货单与对账行，不合并统计|
|EC-04|接单配置改为人工，但已有延迟任务未执行|该店未执行的延迟任务取消；已执行的确认不回滚，仅流转记录保留来源|
|EC-05|自动确认与人工确认同时到达|状态变更带前置状态校验，只成功一次；后到者收到冲突提示，不覆盖|
|EC-06|备货日范围起始晚于结束|前端拦截并提示「起始备货日不能晚于结束备货日」，范围不写入|
|EC-07|某商品某门店未订货|门店列该格显示「未订」，不按 0 参与缺口判断|
|EC-08|预告缺口大于下单量|建议备货不允许为负；按业务规则校验预告提交，异常由缺货预告模块拦截|
|EC-09|D03 视口高度很小|表头与汇总栏固定，表格内部纵横滚动；不出现整页滚动条|
|EC-10|发货行实发量填 3.5 件|自动取整为 4 并提示；仅计重单位允许 1 位小数|
|EC-11|未勾本行不发但实发量留空 / 为 0|保存拦截，列出问题行号，输入框红框、整行浅红底|
|EC-12|供应商只想先存一半|「保存」写入待发货单并记时间，但不锁定、不生成送货单；不算确认发货|
|EC-13|确认发货后报告未齐|不提示、不阻塞；报告是合规凭证，不进金额链路|
|EC-14|报告有效期覆盖发货日期但已作废|不进候选、不自动关联；历史已引用记录仍可查|
|EC-15|报告对应的商品改名或改包规|按 pid / sid 匹配，引用不断链；详情仍显示当时关联报告|
|EC-16|报告被作废后历史发货单查看|显示该报告并标注已作废，不追改引用|
|EC-17|食安报告文件上传了 PDF / XLSX|缩略图与放大预览均可用；文件与图片混排，不做类型分类|
|EC-18|E04 待发货态想补报告|本页整列只读且不显示 E02 跳转提示；补充在 E02 明细行内完成|
|EC-19|E04 已发货态想替换报告|不提供替换 / 解绑，只允许追加补传|
|EC-20|送达时间留空|E01 配送时间与 E04 / K05 仅显示配送日期，不报错、不阻断确认|
|EC-21|整单未发|按实发量 0 确认发货并生成 0 元发货单与送货单，避免订单永久停在「已确认」|
|EC-22|门店尚未验收但发货单已确认|状态显示「已发货 · 待验收」；E04 不显示「看验收结果」入口|
|EC-23|验收单与已完成订单不一致|`shipAudit()` 双向校验并告警：挂验收单必已完成、已完成必有验收单|
|EC-24|验收结论有拒收|合格量 = 实收 − 拒收，结算金额按合格量现算，差异行标红|
|EC-25|退货申请超过 72 小时未处理|系统默认同意，流转记录标注超时；对账自动扣减|
|EC-26|退货申请被驳回|状态「已拒绝」，处理说明必填；原结算不变|
|EC-27|退货数量大于该商品合格量|提交前拦截并指出超过数量；退货只扣减已通过数量|
|EC-28|对账筛选只选档口未选门店|档口下拉禁用并提示「请先选择门店」，避免跨店同名档口误选|
|EC-29|对账记录被筛选到空|列表显示空态，KPI 与筛选条件同步；不伪造记录|
|EC-30|对账明细切换每页条数后页码失效|`pgSlice()` 做越界兜底，落到有效页；统计口径不变|
|EC-31|F05 进入 D02 后返回|D02 顶部显示「返回详情」，点击回到原退货单 F05，不清空 `CUR_RETURN_NO`|
|EC-32|E11 筛选无匹配报告|显示“没有匹配当前筛选条件的报告”，可点「重置」查看全部|
|EC-33|导出超过上限|单次上限 5,000 行，超限按配送日拆分；导出记录含操作人与时间|
